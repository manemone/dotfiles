# 計画書: 司令官と担当の会話で Figma のデザインを作り込む手順をスキルにする

傘ブランチ: `figma-design-workflow`
ターゲット: `master`

## 概要

傘ブランチ（司令官1人＋孫の会話）の進め方で、Figma の画面の叩き台を作り込んでいく手順を、
`skills/figma-design-workflow/` のスキルにする。材料は、ある業務アプリの画面の Figma 叩き台を、
司令官1人＋担当（孫の会話）3人＋Codex のレビュワー・画像生成役で作り込んだ傘（約2週間・記録 80 本超）の実績と、
その傘で書かれた知見の文書。

既存のスキルは、Figma のような**リポの外にある正本**を担当が書き換える作業を扱っていない（背景3）。
この傘で、体制・1件の流れ・ユーザーとのやり取り・Figma の安全・パターン・点検スクリプトの雛形・
実装への受け渡し・よく指摘されることを、**固有名詞と固有の決めを抜いて**一般的な手順にする。

## 決定的な制約（孫は全部守ること）

- **この dotfiles は公開リポ。材料の固有名詞・中身を持ち込まない**: 会社名・製品名・顧客・画面名・人の名前・Figma の
  ファイルキーやノード id・社内のリポ名・Slack のチャンネル・個人の情報。例は一般的な業務画面の言い方
  （「一覧画面」「詳細画面」「集計の画面」など）に置き換える。ファイル名・コミットメッセージ・PR 本文・ADR も同じ
- **材料に固有の決め（色の段の具体値・アイコンの選び方・字の段の数値・すき間の段の数値）はスキルに入れない。**
  「決まりを作って点検する」という手順と、決めるときの観点だけにする。数値の例が要るときは、材料の値ではなく
  明らかに例とわかる丸い値（「例: 4 の倍数」など）にする
- 人間の発言を逐語で書かない（要約する）。レビュー・ユーザーの指摘を引くときも、指摘と決定だけにする
- dotfiles の `AGENTS.md` の規約に従う: スキルは AI 不問の自然言語（YAML frontmatter を除く。ADR DOC-2608272128）、
  確定した技術決定は ADR、`docs/` の文書への言及には DOC-ID を明示する
- **既存のスキルと重複させず、参照でつなぐ。** 孫の spawn・マージ・巡回は umbrella-orchestrator、PR のレビューの往復は
  pr-review-loop、実装の画面の確認は ui-review、作業の振り分けは task-intake。Figma の API の使い方そのもの
  （use_figma の書き方など）は Figma 公式のスキル（figma-use など）に任せ、このスキルには書かない
- 点検スクリプトを雛形として入れるときは、特定のファイルの名前・id・決まりの値を抜き、決まりの表を差し替えられる形にする
- deploy はしない（配るのは人間）。`deploy-all.sh` も実行しない
- 材料のリポ・製品のリポ・Figma の実ファイルには書き込まない（読むだけ。issue へのコメントもしない）

## 必須の検証ステップ（dotfiles AGENTS.md「コミット前の必須ステップ」より。省略しない）

- `pre-commit run --files <変更したファイル>`（まとめてなら `pre-commit run --all-files`）
- `docs/` に新規ファイルを足すときは `DOC-DOCID_PLACEHOLDER_<名前>.md` で作り、`./tools/doc-id/doc-id assign <path>` で採番、
  `./tools/doc-id/doc-id verify` を通す。**このマシンでは Ruby の既定の文字コードが US-ASCII になっていて `doc-id` が
  `incompatible character encodings` で落ちるので、`LC_ALL=C.UTF-8 ./tools/doc-id/doc-id …` のように付けて叩く**
- **公開リポの照合（PR ごと。省略しない）**: 次の結果が0件であること。当たったら言い換える（照合リストを緩めない）。
  時刻（`18:20` など）が最後のパターンに当たるのは誤検知なので、目で見て除いてよい

  ```bash
  git fetch origin
  git diff origin/figma-design-workflow...HEAD | grep -n -i -E -f ~/.local/state/umbrella/figma-design-workflow/denylist.txt
  ```

  照合リストはリポの外のファイルで、材料を読んで新しい固有名詞（人名・画面名など）に気づいたら足してよい。
  リストに無くても、材料にしか出てこない名前・画面名・具体値を書いていないかを自分で読み直す
- 詳細は AGENTS.md「コミット前の必須ステップ」と DOC-2610150520
- **このマシンの push**: リモートが https で git の認証ヘルパーが未設定のため、素の `git push` は
  `could not read Username` で落ちる。設定ファイルは変えず、その1回だけ gh の認証を使う:
  `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push -u origin <ブランチ>`

- 日本語の自然言語。既存のスキル（ui-review・pr-review-loop）の文体に合わせ、平易な言葉で書く

  ファイルの先頭にまとめ**、利用者がそこだけ差し替えれば使える形にする

- 実行は Figma の MCP（use_figma など）経由で、**読むだけ**（書き込みをしない）を守る
- 構文の確かめは `node --check skills/figma-design-workflow/references/audit-template.js`（Figma の外では動かないので、
  構文だけ）

spawn・マージの手順と関心が違う／Figma を使わない傘には不要）、既存スキルとの分担（設計0 の 2 の最後の行と、
