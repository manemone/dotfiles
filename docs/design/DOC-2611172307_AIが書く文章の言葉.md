# AI が書く文章の言葉

読み手が人間でも AI でも、書いた文章全般（会話の返事・他の AI への指示・AI が読むスキルや指示文・PR 本文・文書・メモ）を書くときの、言葉の基準です。
対象は、このリポジトリで作業する AI と、ここから配る `claude/CLAUDE.md` を読む AI です。

この基準は、持ち主が何度も指摘しても直らなかった3つの癖を、禁止の列挙ではなく「何をどう書くか」と
「それで読み手に何が起きるか」で書き直したものです。語のリストで判定する文書ではありません。
例は考え方を示すためのもので、対象の全部ではありません。**例に無い場合も、各節の目標と理由に立ち戻って判断します。**
同じ語でも、読み手と文脈によって適切にも不適切にもなるためです。

## 1. 読み手がその文脈で実際に使う名前で書く

### 目標

物事を指すときは、読み手がその分野・その文脈でふだん使っている名前で書きます。
同じ物事は、文章の中で同じ名前で呼びます。名前が無い、または定着していないものは、
実物や実際の動作をそのまま説明します。

### 理由

読み手は、書かれた名前を自分が使っている名前へ頭の中で変換してから読みます。
別の言い方に置き換えられると、その変換が毎回増えます。置き換えた側の語は意味の幅も広く
（たとえば「直す」は、修正・修理・変換・復元のどれにも読めます）、指示としては曖昧になります。
同じ物事を違う名前で呼び分けると、読み手は別の物事が出てきたと受け取ります。

### 境界

基準は、語の出自（和語・漢語・カタカナ）ではなく、**読み手がその文脈で実際に使う名前かどうか**です。

- 持ち主が自分で使う和語は、そのまま使います。「引く」「探す」「立てる」「止める」「回す」などです。
  これらを別の言い方にすると、逆向きの誤りになります
- カタカナ語も、読み手の文脈で定着しているものはそのまま使います（シード、キャッシュ、トークン、コピーなど）
- 定着していないカタカナ語や、書き手だけが使う略語は、読み手の名前ではありません。最初に実物を説明するか、
  読み手の名前で書きます
- 同じ語でも文脈で変わります。数学の文脈の「確かめ」は普通ですが、ソフトウェアの作業で「確認」と呼ぶ場面を
  「確かめ」と書くと、読み手の名前から外れます

### 良い例と悪い例

悪い例は向きがばらばらです。向きを問わず、読み手の名前から外れていることが問題です。

| 型 | 悪い例 | 良い例 | 外れている理由 |
|---|---|---|---|
| 定着した漢語を和語に開く | 設定を確かめる／コードを直す／結果を測る | 設定を確認する／コードを修正する／結果を計測する | 読み手の名前へ変換し直す手間が増える。「直す」は意味も開く |
| 定着したカタカナ語を日本語にする | 乱数の種を固定する／控えを消す／写しを取る | シードを固定する／キャッシュを消す／コピーを取る | 読み手は「シード」「キャッシュ」で検索し、会話し、設定する |
| 定着していないカタカナ語を押し通す | 処理時間のスパイクが出た／設計がドリフトしている | 処理時間が急に長くなった／実装が設計から外れている | 読み手はその語を使わず、意味を推測する羽目になる |
| 英語の直訳の造語 | 壊れ方が静か／重い持ち上げ作業 | エラーを出さずに失敗する／負荷の大きい処理 | 日本語として定着した言い方ではなく、元の英語を知らないと読めない |
| 中の部品に付けた造語のラベル | 焼いた指示書（生成して埋め込んだ指示書） | 埋め込み済みの指示書 | ラベルを知っているのは書き手だけ。説明なしに出ると別の物に見える |
| 定着した用語を比喩で呼ぶ | API トークンを「ダウンロードの合言葉」と呼ぶ | API トークン | 読み手は用語で検索・設定する。比喩からは元の用語にたどり着けない |
| 言い換えで変化を付ける | 同じファイルを「設定」「ファイル」「定義」と書き分ける | 初出で名前を決め、以降は同じ名前を使う | 書き分けると、読み手は別々の物が出てきたと受け取る |

### 書くときの確認

名前を選ぶとき、「この読み手は、この物事をふだんどう呼ぶか」を考えます。読み手の呼び方が分からないときは、
コードや文書の中で実際に使われている名前を探します。物事の名前が無いなら、造語を作らず、実物か動作を説明します。

## 2. 決まり文句の代わりに、中身を書く

### 目標

その文脈でしか言えない中身（具体的な主張・数字・実物・手順）を書きます。どの文章にも当てはまる言い回しで
文を埋めません。

### 理由

決まり文句は、書くべき中身が無いか、まだ決まっていないときに出ます。読み手は文の頭で、その先の中身を
期待して読みますが、決まり文句には中身が無いので、読む時間を使っても得られるものがありません。
語だけを機械的に取り除いても、中身が無いことは直らず、別の決まり文句が出ます。

### 境界

- 手順の見出し・定型の書式（PR 本文の「背景」「目的」など）は決まり文句ではなく、構造です
- 結論を先に言うこと自体は良い書き方です。問題は、結論を言わずに「結論から言うと」と前置きだけ置く書き方です
- 丁寧語・口調は、`CLAUDE.machine.md` が定める人格の範囲で、この基準の対象ではありません

### 良い例と悪い例

| 悪い例 | 良い例 | 何が違うか |
|---|---|---|
| この設計の本質は、責務の分離です | 取得と整形を別の関数に分けたので、整形だけを単体でテストできます | 「本質」と言うだけで、何がどう良いかを書いていない |
| 結論から言うと、問題ありません | 3ファイルとも差分は空白だけで、動作は変わりません | 「問題ない」の根拠（差分の中身）を書いていない |
| いくつかの点で改善が見られます | 応答時間が 420ms から 180ms に下がりました | 数字があれば言い切れる |
| 重要なポイントは次のとおりです | （そのまま重要な内容を書く） | 前置きは読み手の時間を使うだけ |

### 書くときの確認

文を書いたあと、「この文は、この文脈の外でも同じ形で通用するか」を考えます。通用するなら、
具体的な値・名前・条件を足すか、文ごと削ります。

## 3. 指摘は、その場面の話として受け取る

### 目標

「この場面でのその判断が悪い」という指摘を受けたら、その場面の何が悪かったかを把握し、その場面で修正します。
規則として書き残すのは、人間がそう頼んだときか、場面を越えて同じ判断が成り立つ理由があるときだけです。
書くときは、適用する範囲と理由を一緒に書きます。

### 理由

指摘を「今後は一切しない」という規則に置き換えると、次から自分で判断する必要がなくなります。
規則に従っていれば考えずに済み、外れても「言われたとおりにした」と言えます。しかし、場面が変われば
正しい判断も変わるので、規則を守ったことが別の場面で誤りになります。
また、書き残した規則は、メモや他の会話への指示へ広がり、元の指摘より遠くまで効きます。

指摘の本来の中身は「その場面の判断の誤り」です。誤りを修正するには、何を見て、何を取り違えたかを理解する必要があります。

### 境界

- 人間が「今後〜しないでほしい」と頼んだなら、その規則は書いてよいものです。頼まれた範囲を超えて広げません
- 場面を越えて成り立つ理由があるなら、規則にしてよいものです（たとえば、特定のツールが特定の条件で必ず失敗する、
  という事実）。そのときも、理由と適用範囲を添えます
- 指摘を受けて、同じ会話の中で同じ誤りを繰り返さないのは当然のことで、規則に残す必要はありません

### 良い例と悪い例

| 場面 | 悪い例 | 良い例 |
|---|---|---|
| 「ここでカタカナ語の説明が無いのは読みにくい」と指摘された | 「カタカナ語は今後一切使いません」とメモに書く | その文書の読み手には「シード」が通じないと認め、その場で実物の説明を足す。定着した語はそのまま使い続ける |
| 長いログを貼って文脈が膨らんだと指摘された | 「ログは二度と貼りません」と宣言する | そのときのログは要点だけで足りたと理解し、貼る量をその場で絞る。必要な場面では貼る |
| 規則として残すよう頼まれた | 頼まれた範囲を超えて、関連する別の規則まで書き足す | 頼まれた規則を、適用範囲と理由を添えて書く |

### 書くときの確認

指摘を受けたとき、「この指摘は、どの場面の、どの判断についてか」を言葉にします。それを言えないまま
規則を書こうとしているなら、規則で判断を省略しようとしています。

## この基準の使い方

- 文章を書く前後に、1〜3 の各節の「書くときの確認」を使います
- 他の文書を書き直すときは、意味を変えず、言葉と文の組み立てだけを書き直します。規則・手順・条件・数値・参照先は、元のとおりに保ちます
- 基準の適用範囲は、読み手が人間でも AI でも、書いた文章全般（返事・他の AI への指示・AI が読むスキルや指示文・PR 本文・文書・メモ）です。コード・コマンド・識別子・引用は対象外です
- 基準自体の効果は、過去の返事を文脈で判定する方法で計測します。計測の方法と値は
  [DOC-2611172119](../reference/DOC-2611172119_言葉の悪癖を抑える仕組みの調査結果.md)、採用の理由は
  ADR [DOC-2611172307-a](../adr/DOC-2611172307-a_言葉の基準と計測の方法.md) を参照してください
