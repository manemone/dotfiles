# ADR: UI 確認はサブエージェントではなく別のペインの確認役に頼む（`ocw checker`）

## ステータス

決定（2026-11-03）。傘 `ds-cost-down`（計画書 DOC-2611032048）の孫3 で決めた。

## 1. 背景

UI の見た目の確認は、これまで実装役がサブエージェント（確かめ役）に頼んでいた。サブエージェントは
実装役のペインの外から見えず、`ocw self-compact` が届かないため文脈が伸び続け、確認のたびに撮影方法を
探し直して試行錯誤する。claude-ds では費用の大半が長い文脈での呼び出しから出ており（計画書 背景4）、
確認役を別の会話にして、渡すものを固定し、人間が見られて compact できる形にしたい。

## 2. 画像読み取りの確認（2026-11-03、手で行った実験）

deepseek-flash が画像を本当に読めているかを確かめた。

- **公式の文書。** DeepSeek の Anthropic 互換 API の文書は、`deepseek-flash` が user メッセージと
  `tool_result` の画像（base64・url・file）を扱うと書く。`deepseek-v4-pro` は画像を処理せず
  `[Unsupported Image]` に置き換える。assistant メッセージの画像は 400 エラー
- **実測。** 乱数で作った5文字の英数字と、色の付いた図形3つ（赤い四角・青い円・緑の三角）を並べた
  PNG を作り、`claude-ds -p`（deepseek-flash）と `claude -p --model sonnet` に Read で読ませた。
  どちらも文字を正しく読み、図形の色と左から右の並びも正しく答えた。推測では当てられない文字列を
  正しく読んだので、deepseek-flash は画像を見ている
- **限界。** 試したのは大きな文字と単純な図形1枚ずつだけ。小さい文字・細かいレイアウトのずれ・色の
  微差を、Claude と同じ精度で読めるかは確かめていない

## 3. 決定

### 3.1 置き場所: `ocw` のサブコマンド `ocw checker`

| 候補 | 評価 |
|---|---|
| `ocw checker`（採用） | 既存の `ocw -H` のペイン構成・`OCW_*_COMMAND` の流儀・`pane_command_with_name` を流用でき、宛先の取り違えをコードとテストで守れる。新しい配布先が要らず `links_for_tool()` / `skill_links()` を触らない |
| `pr-review-loop` の節 | UI 確認は PR レビューの一部ではなく、実装の途中や PR 前にも要る。レビューの手順に結合させると使いにくい |
| 新しいスキル | 起動と宛先の安全をプロンプトに頼ることになる。スキルは配布先と一覧の管理が増える。使い方は `ocw help checker` と `bin/README.md` に書けば足りる |

### 3.2 形

- 実装役が `ocw checker <リクエストのディレクトリ> [--wait <秒>]` を打つ。ディレクトリには撮影スクリプト
  `shoot.sh` と確認項目 `checklist.md` を置く。確認役はそれを流し、`result.md` に結果を書いて短く要約を返す。
  **確認役に撮影方法を探させない**（試行錯誤を防ぐ）
- 初回は実装役のペインの下に確認役のペインを分割して起動し（人間が同じワークスペースで見られる）、
  ペイン ID を `.git` 内の `ocw-checker-pane` に控える。2回目以降は生きていればそのペインへ送り、
  文脈を引き継ぐ。エージェントが消えている・控えが自分自身のペインを指す場合は作り直す
- 宛先は `ocw` が作って控えたペインだけ。実装役自身のペインへは送らない
- 結果は `result.md.tmp` に書いてから `result.md` へ移す。`ocw` は送る前に古い `result.md` を消す。
  `--wait` は `result.md` を一定間隔で見に行く（現れたら 0、時間切れは 3）

### 3.3 既定のモデルと費用

既定は Claude の Sonnet（`OCW_CHECKER_COMMAND` の既定 `claude --model sonnet`）。`claude-ds` や codex 等へは
環境変数で上書きできる。

- **Claude を既定にする根拠。** §2 のとおり deepseek-flash は画像を読める。それでも既定を Claude にするのは、
  UI の確認は小さい文字・細かいずれ・色の微差を見分ける仕事で、§2 の限界のとおり deepseek-flash の精度を
  確かめていないため。確かめ役が見落とすと、実装役が直す回数と文脈が増え、節約が崩れる。確かめられたら
  既定を変える余地がある
- **費用。** Sonnet はサブスクの枠内で動くので、ドルでは比べない。効くのは**週の上限の減り方**で、確認役を
  増やすほど Sonnet の分が減る。サブエージェントで頼んでいたときの Sonnet 消費と同じ種類の消費が、
  別の会話に移るだけで、増えるかどうかは確認の頻度と確認役の文脈の長さによる
- 試算や週の上限の実測は、傘の最終 PR のあとの宿題（計画書 必須の検証ステップ）で見る

### 3.4 確認役の self-compact

確認役は普通のペインで、`OCW_ROLE=checker` を持つ。`ocw self-compact` は自分のペインにしか送れないため、
**実装役が確認役を外から compact することはできない**。そこで、依頼文（`checker_prompt`）で確認役に
「要約を返したあと、文脈が 200,000 トークンを超えていれば自分で `ocw self-compact` する」と頼む。
閾値は現行の規則（ADR DOC-2610142337）に合わせた値で、孫2 が見直したら合わせて更新する。

compact の完了後に watcher が送る復帰プロンプトは、`OCW_ROLE=checker` のときだけ専用の文
（「実装作業は始めない。次の依頼を待つ」）にする。既定の文（計画書の続きから再開）のままだと、
確認役が実装役と同じワークツリーで実装を始めかねないため。

## 4. 通常の Claude の会話への影響

新しいサブコマンドと環境変数 `OCW_CHECKER_COMMAND` を足すだけで、既存の `ocw` の動作・`claude/` 配布物・
`settings.json` は変えない。`ocw checker` を打たない限り何も起きない。

`claude/settings.json` の `permissions.allow` に `Bash(ocw checker *)` は**足していない**。自動承認の拡大は
人間が決めることなので、分類器に止められた場合は人間が許可する（足すなら `ocw self-compact` の
ADR DOC-2610130913 と同じ理由で、宛先が自分で作ったペインに限られることを根拠にできる）。

## 5. 却下した案

- サブエージェントのまま、撮影スクリプトだけ固定する: 文脈が伸びても `ocw self-compact` が届かず、
  人間が見られない
- 確認役を毎回新しい会話にする: 毎回、確認の前提を読み直す費用がかかる。生きていれば再利用し、
  膨らんだら作り直す
