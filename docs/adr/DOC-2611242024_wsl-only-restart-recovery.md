# ADR: WSL だけが起き直したときにも `rebootctl boot` を動かし、起動時の差し込み口を足す

## ステータス

確定（2026-11-24）。ADR DOC-2611151248（rebootctl の Windows 起動）の起動の方式 A を拡張する。

## 1. 背景

WSL だけが落ちて起き直した（Windows 本体は再起動していない）。`rebootctl boot` は Windows のタスクの起動時トリガーでしか
動かないので、会話は持ち主が手で起こすまで止まり、落ちたことも知らされなかった。

## 2. 決定: タスクに5分おきの繰り返しを足す

起動時のタスクに、5分おきの繰り返しを足す。`boot --hold` は WSL が生きているあいだ居座って終わらず、複数起動は
`IgnoreNew` で無視されるので、繰り返しが効くのは WSL が落ちて `wsl.exe` が終わったあとだけになる。次の繰り返しが WSL ごと
起こして `boot` を呼ぶ。**WSL が落ちたまま起き直さない場合も最大5分で拾う。** 拾えないのは Windows 自体が止まっているとき。

同じ起動で走り直さないよう、`boot --once-per-boot` を足した。この起動で `boot` が最後まで終わっていれば（`boot-state.json` の
`finished`）、何もせず居座るだけにする。`--once-per-boot` の無い `boot`（手で叩く・古い形のタスク）は今までどおり何度でも走り、
同じ起動での二重の通知は管制の会話の `notified_boot_id` が防ぐ。Windows の再起動のときの起動時トリガーの振る舞いは変わらない。

## 3. 却下: WSL の systemd のユニット

WSL の中の systemd の起動時ユニットで `boot` を呼ぶ案。配布の仕組み（`links_for_tool()`・世代・アンインストール）に
ユニットの置き場を足す必要があり、WSL が落ちたまま起き直さない場合は拾えない。タスクの繰り返しなら、登録の1か所で
両方を満たす。

## 4. 決定: 起動の種類を `boot_id` と Windows の最終起動時刻で決め、通知文に出す

`boot_id` が前回の記録と違うとき、Windows の最終起動時刻が前回と同じなら `wsl_restart`、違えば `windows_reboot`、
読めない・前回が無ければ `unknown`。同じ `boot_id` の再実行は最初に決めた種類を使う（自分の記録と比べて取り違えない）。
記録は `${XDG_STATE_HOME:-~/.local/state}/reboot-recovery/boot-state.json`。管制の会話（スキル `control-tower`）がこれを読み、
今の通知の経路で1回だけ、種類が分かる文面で知らせる。新しい通知の経路は足さない。

## 5. 決定: 起動時の差し込み口

`${XDG_CONFIG_HOME:-~/.config}/reboot-recovery/boot.d/` の実行ファイルを、`boot` の最初（会話の復元を待つより前）に名前順で
呼ぶ。1本ごとに60秒の上限を付け、失敗・時間切れでも続ける。出力は `boot.log`。起動の種類などを環境変数で渡す。
決まりの全体は `bin/README.md` §3.7。呼び先を会話の復元より前にしたのは、呼ばれた側の処理（時間のかかる再開など）を
早く始めるためで、1本あたりの上限で復元を遅らせる最大を抑える。呼ばれる側は何度呼ばれても害が無いように作る。
