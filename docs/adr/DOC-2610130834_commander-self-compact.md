# ADR: 司令官が自分自身の文脈を縮める手段（自己 compact）

## ステータス

調査完了（2026-10-13）。孫4 がこの結論をスキルに反映する。人間に判断してほしい点は §8。

## 1. 背景

傘の司令官は巡回 cron を抱えて長く生きるので、会話の文脈が膨らみ、idle の tick（何もしない
巡回）でも毎回その全体を読み直す費用がかかる（計画書 DOC-2610122205 背景2・設計2.1）。
`skills/umbrella-orchestrator/SKILL.md` §3.7 は現状「300k を超えたら区切りで compact を提案する」
だけで、司令官は自分では `/compact` を打てない前提だった。本 ADR は次の候補を確かめ、
司令官が自分で文脈を縮められるかを決める。

- (a) 自分のペインへ `herdr agent prompt` で `/compact` を送る
- (b) 自動 compact の閾値を下げる
- (c) `/clear` や引き継ぎで会話そのものを入れ替える

## 2. 実測

### 2.1 条件と作法

- Claude Code 2.1.296。孫2 の自セッション（Herdr ペイン、`$HERDR_PANE_ID`）を被験体にした
- 当初は使い捨ての Herdr セッションで使い捨ての claude を起動する計画だったが、分類器に拒否された
  （§2.3）。司令官が実際に compact したいのは自分自身なので、自セッションを被験体にする方が本番に近い
  として方式を変えた
- compact 前に、状態と次の手順をリポ外のメモ（スクラッチパッド）へ書き出した。`/compact` の引数には
  「メモと正典の計画書を読み直せ」とだけ渡した。compact 後の自分はこのメモで復帰できた
- 試験用 cron を `*/7 * * * *` で1本登録した（本文は「`tick` とだけ答える」。作業は進めない）
- 計測は会話ログ `~/.claude/projects/<プロジェクト>/<セッションID>.jsonl` の
  `system / compact_boundary` 行（`compactMetadata`）と、assistant 行の `usage` から読んだ

### 2.2 結果

| 項目 | 結果 |
|---|---|
| 人間が `! herdr agent prompt "$HERDR_PANE_ID" "/compact …"` を1回打った | ペインは `working` になり、現ターンの終了後に `/compact` が走った |
| herdr 経由の `/compact` はコマンドとして実行されたか | **された。** ログに `<command-name>/compact</command-name>` が記録され、`compact_boundary` の `trigger` は `manual` |
| compact 前の文脈 | `preTokens` = 104,596 |
| compact 直後の会話 | `postTokens` = 5,902（要約＋保持した末尾3メッセージ。差し引き 98,694 を落とした） |
| compact 後の最初のリクエストの全入力 | 57,378（cache_read 28,115 + cache_creation 29,263）。system プロンプト・ツール定義・CLAUDE.md などの固定分が約 5 万あり、会話の `postTokens` に足される |
| compact に要した時間 | `durationMs` = 32,981（約33秒） |
| compact 1回の費用 | 要約生成の呼び出し1回。入力は `preTokens`（約 10.5 万）、出力は要約本文。**要約呼び出し自体の `usage` はログに残らない**ため、トークン数の内訳は測れていない（§7） |
| 試験用 cron は compact をまたいで残ったか | **残った。** compact 直後の `CronList` に同じジョブ ID・同じ本文で現れた（session-only のまま） |
| compact 直後のセッション間メッセージ | compact 完了（23:32:31）の約1分後（23:33:30）に司令官からのメッセージが届き、通常どおり処理された。**compact 実行中（約33秒間）に届いた場合は観測していない**（その間にメッセージも tick も到着しなかった。§7） |
| compact 後の自動再開 | **しない。** 要約の直後にセッションは idle で止まり、次の入力（司令官のメッセージ）が来るまで動かなかった |
| compact 前の idle の費用 | compact 前に tick が約 50 回発火した。各 tick は約 10.3 万トークンのキャッシュ読み出し＋数十の書き込みで、答えは `tick` の数トークンのみ。**文脈が小さければ、この 1 tick あたりの読み出しがほぼそのまま減る** |

ただし tick は compact 直後の観測窓（約2分）では発火しておらず、「compact 後も cron が発火し続ける」
ことまでは確かめていない（`CronList` に残っていることだけを確認）。

### 2.3 分類器（auto mode）に拒否された操作

どちらも拒否を回避せず、そのまま記録する。

- **`[Create Unsafe Agents]`**: 使い捨ての Herdr ワークスペースで `herdr pane run … claude …` を
  起動する操作が、`--allowedTools` の有無にかかわらず2回拒否された。使い捨てセッションに
  claude を起こす方式は auto mode では取れない
- **`[Tmux Self Drive]`**: 自分のペインへ `herdr agent prompt "$HERDR_PANE_ID" "/compact …"` を送る
  操作が拒否された。**人間が `!` で手で打てば通る**（人間の入力であり分類器を経由しない）

## 3. 方式の比較

### (a) 自ペインへ `herdr agent prompt` で `/compact` を送る

- 仕組みとしては成立する（§2.2: コマンドとして実行され、cron は残り、メッセージも処理される）
- **ただし auto mode では AI が自分では送れない**（`[Tmux Self Drive]`）。人間が打つ（または人間が
  承認する）形に限られる。司令官が自分で送る専用コマンドを作り、それだけを許す絞った permission
  ルールを足す案は、ルール追加が人間の承認事項なので本 ADR では採否を決めない（§8）
- 実行は現ターンの終了後。送ったあとはターンを終え、compact の完了を待つ
- compact 後は自動では再開しないので、続きを促す入力が別に要る（§6）

### (b) 自動 compact の閾値を下げる

Claude Code 2.1.296 のバイナリ（`strings`）と、公式ドキュメント
（<https://code.claude.com/docs/en/env-vars>、2026-10-13 に確認）で調べた。**実起動では試していない**
（env を変えた起動は司令官の起動方法に踏み込む）。

公式ドキュメントで裏が取れた点:

- `CLAUDE_CODE_AUTO_COMPACT_WINDOW` は自動 compact の窓をトークン数で指定する。範囲は
  `100000`〜`1000000`、**素の整数のみ**（`500k` は `500` と読まれて下限 100K に丸められ、
  エラーも出ない）。実効の窓はモデルのコンテキスト窓で上限が切られる。`/autocompact`・
  `--autocompact` フラグ・設定 `autoCompactWindow` より優先される。ステータスラインの
  `used_percentage` はモデル全体の窓に対する割合なので、設定後は compact の時期の目安にならない
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` は自動 compact が走る窓の割合（1〜100）を指定する。
  **閾値を下げる方向にしか効かず**、既定より大きい値は無視される。「モデルのコンテキスト上限より
  前に compact するセッション」でのみ効く。**メインの会話だけでなくサブエージェントにも効く**

バイナリのみで確認し、公式ドキュメントの該当範囲では裏が取れなかった点:

- `DISABLE_AUTO_COMPACT` は自動 compact を止める。`DISABLE_COMPACT` は手動 `/compact` も止める
- `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` という変数が存在する（用途は未確認）
- 閾値は「窓 − 要約用バッファ」で決まる、という式（ここでは式の確認は取れていない）
- `claude/settings.json` は `autoCompactEnabled: true`

**却下ではなく補助。** 自動 compact は「いつ発動するか」を選べず、巡回の途中や PR の
レビュー待ちの最中にも走りうる。区切りで縮めたい司令官の用途には、単独では合わない。ただし
「上限の安全網」として閾値を下げる使い方は妥当。その場合の落とし穴は上記のとおり（書式・下限・サブエージェントへの波及。§8）。

### (c) `/clear` や引き継ぎで入れ替える

机上比較のみ（`/clear` は自分の作業文脈を消すため、被験体の自セッションでは試していない）。

- `/clear` は会話を空にする。cron は session-only なので、再登録のための情報を事前に外へ
  書き出しておく必要がある。復帰は人間か別セッションからの入力に頼る
- 引き継ぎ（新セッションを起こして継がせる）は、`[Create Unsafe Agents]` に当たる可能性がある（§2.3）。
  また傘の司令官は他の孫・巡回 cron と結び付いており、入れ替えの手間が大きい
- compact は要約を残して cron を保つので、同じ「縮める」目的でも (c) より安全

## 4. 採用する方式

**(a) 自ペインへの `/compact`。ただし auto mode では人間が打つか承認する。** AI が自分で送る前提を
スキルに書かない。補助として (b) の閾値引き下げを人間が環境側で設定できる（採否は §8）。

## 5. 孫4 がスキルに書くべき要点

1. 区切りを見極める（承認報告を送り終えた直後・孫の完了待ちで何も進行中でないとき）。文脈が閾値
   （現状 SKILL.md §3.7 の 300k）を超えたら、人間に「いま compact していいか」を**提案する**
2. 提案には、人間がそのまま打てる1行を添える。**司令官のペインで打つ前提なら、herdr を経由せず
   そのペインで `/compact <復帰メモの場所と、正典の計画書の指示>` を直接打てばよい**（本実測で
   `herdr agent prompt` を使ったのは、人間の入力としての実行にこだわらず herdr 経由の配送を
   確かめるためで、運用では遠回り）。別のペインから打ちたい場合は、`$HERDR_PANE_ID` が打った
   側のペインに展開されて別セッションを compact してしまうため、司令官が提案時に自分のペインIDを
   解決し、展開済みの値を埋めた `! herdr agent prompt <実際のペインID> "/compact …"` を出す
3. **自分では `herdr agent prompt "$HERDR_PANE_ID" …` を送らない**（auto mode で拒否される。
   回避も試みない）
4. 送る前に、状態（進行中の孫・待ち中の PR・登録済み cron の本文と間隔）をリポ外のメモへ書き出し、
   `/compact` の引数でそのパスを指す。compact 後の自分は、メモを最初に読んで復帰する
5. cron は compact 後も `CronList` に残ることまでは確認済みだが、**発火し続けることは未確認**（§7）。
   `CronList` で残存を確認しても安心せず、compact 後の最初の予定時刻（最大でも間隔の1周期）を
   過ぎても tick が来なければ、重複しないよう `CronList` を見直したうえで再登録する。残っているのに
   再登録しない・残っているのに重複して登録する、のどちらにもならないようにする
6. compact 後は自動再開しない。続きを動かす入力（人間のひとこと、または他セッションからのメッセージ）が要る。
   「compact 後に何をするか」を復帰メモの先頭に書き、人間にも「compact が終わったら続きをと一声かける」ことを伝える
7. 実行中は新しい作業を始めない。送った直後のターンで終える

## 6. 自動化するときの注意

- compact が終わったあとセッションは idle で止まり、自分からは続きを始めない（司令官が観測。
  本実測でも同じ）。完全自動にするなら `/compact` の後に続きを促す入力も要る。しかし
  その入力を AI が自分のペインへ送る経路も `[Tmux Self Drive]` に当たりうるため、自動化は
  人間の承認を要する前提で設計する

## 7. 残る不確かさ

- 要約呼び出し1回の入力・出力トークンの内訳は、ログに残らず測れていない。`preTokens` から
  入力は約 10.5 万と見積もれるだけ
- compact 後も cron が発火し続けるかは、観測窓が短く未確認（ジョブが残ることのみ確認。compact 完了 23:32:31 のあと、次の予定時刻 23:37 の前に試験用 cron を削除した）
- compact **実行中**にセッション間メッセージや cron の tick が届いた場合の扱い（処理される・捨てられる・要約に飲まれる）は未観測。孫4 は「未処理の報告が無い区切りを選んで送る」を前提にし、この挙動に依存しない
- 被験体は auto mode の自セッション1つ。`default` 権限モードや他の起動オプションでの
  `[Tmux Self Drive]` の挙動は見ていない
- (b) は実起動での確認をしていない

## 8. 人間に判断・確認してほしい点

1. **司令官が自ペインへ `/compact` を送る専用コマンドと、それだけを許す絞った permission ルール**を
   足すか（足す場合、ルール追加は人間の承認事項）。足さないなら §5 のとおり人間が打つ運用
2. (b) の安全網として `CLAUDE_CODE_AUTO_COMPACT_WINDOW`（素の整数。下限 10万）や
   `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`（サブエージェントにも効く）を環境側で設定するか。設定するなら
   司令官の起動方法（`ocw` 等）への反映は別件
3. Claude Code 以外のエージェント（Codex・OpenCode）の扱い: `/compact`・CronCreate・
   セッション間メッセージはいずれも Claude Code 固有。スキルは配布物なのでエージェント非依存に
   保つ必要がある。**他のエージェントでは「自己 compact の手段が無い」前提で、今までどおり提案のみ
   （区切りで人間に新しい会話への引き継ぎを提案する）に留める**。スキルには「`/compact` は
   Claude Code の場合」と注記し、他のエージェントの類似コマンド（もしあれば）の有無は確かめていない

## 9. 後片付けの確認

- 使い捨ての Herdr セッション `cmpprobe` は停止し、一時ディレクトリは削除済み
- 試験用 cron は `CronDelete` で削除済み
- リポに追加したのは本 ADR と `docs/README.md` の索引行のみ（コード・スキルは不変）
