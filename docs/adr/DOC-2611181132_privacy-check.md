# ADR: 発言の逐語の節を、コミットの時点で止める点検（privacy-check）

## ステータス

決定（2026-11-18）。同日、名前の照合を外す改訂（2.2）。

## 1. 背景

人間の発言の逐語と、非公開のリポジトリの名前が、公開の dotfiles の計画書・文書・PR に入っていた。
履歴と PR の差分に残るので、あとから消すことは事実上できない。決まり（スキルの文）だけでは
再発を防げないため、コミットの時点で機械的に止める点検を足す。

## 2. 決定

### 2.1 形

- `tools/privacy-check/privacy-check` を、`templates/repo-baseline/template/tools/privacy-check/` に同じ実体で
  置いて配る。POSIX sh と awk だけで書き、配る先の言語ランタイムの前提を増やさない
- `pre-commit` の `repo: local` フックを `pre-commit` 段（ファイル）と `commit-msg` 段（メッセージのファイル）の
  両方に登録する。`--stdin` で PR の本文など、ファイルにならないものも通せる
- dotfiles 側と配る側の食い違いは、`doc-id` の複製と同じく `diff -r` の pre-commit フックで検出する
  （どちらか一方を正とする方式にはしない。展開先で道具が自己完結するため）

### 2.2 非公開の名前は機械で照合しない

当初は、非公開の名前の一覧をリポジトリの外（マシンローカルな設定）に置き、点検で突き合わせる設計だった。
持ち主の判断で、これを外した。一覧を作って突き合わせる方法には意味が無いというもの。理由は次のとおり。

- 一覧は名前の置き場になり、載っていない名前は止められない。止められる範囲が、一覧を書いた人の記憶に縛られる
- CI には一覧を置けないので、効くのは手元のコミットだけで、PR の本文など他の経路を覆えない
- 動かない（一覧が無い）仕組みを残すと、名前も点検されていると誤解させる

名前の流出は、スキルの決まりと、レビュワーが差分・PR の本文・コミットメッセージを意味で読んで指摘する観点で止める。
機械で止めるのは、見出しの語で判定できる発言の逐語の節だけである。

### 2.3 出力は行番号だけにする

出力は `<path>:<行番号>: heading` だけにする。人は行番号で見に行く。

### 2.4 見出しだけを見て、地の文は見ない

発言をそのまま載せる節は「見出し + 引用」の形で現れるので、見出しの語（逐語・持ち主の言葉・人間の発言・原文など）で
検出する。地の文の引用と、手順の例として書いた文（人間が「〜しろ」と言ったら、の類）は、語や記号の並びでは
区別できず、誤検出が多い点検は人が許可を広げて骨抜きにする。文中の引用は、スキルの決まりとレビューで止める。
「書かない」ことを述べる見出し（`## リポジトリに書かないもの`、逐語で書かない、など）は否定の語を含めば止めない。
見出しの点検は Markdown（`*.md`・`*.markdown`・標準入力）だけに効かせ、コミットメッセージのような
`#` 始まりの行がコメントになるファイルへは効かせない。

### 2.5 コードブロックの中の見出しも点検する

ブリーフの雛形のようにコードブロックの中の見出しが正当に当たる場合は、行の許可の印
（`privacy-check:allow-line`）で通す。コードブロックを一律に飛ばさないのは、計画書に入れた孫のプロンプトが
コードブロックの中にあり、そこに入った逐語の節を見逃すため。印の追加は、既存ファイルを直す側
（孫3）の作業で行い、この ADR の実装では足さない。

### 2.6 許可

行の印のほか、点検と同じ場所の `allowlist.txt` にリポジトリのルートからの相対パスで書く。
ディレクトリ丸ごとの除外はできない。

## 3. 却下した案

- 名前の一覧をリポジトリの中に置く: 一覧が名前の公開になる
- 名前の一覧をリポジトリの外に置いて照合する: 2.2 の理由で外した
- 地の文の引用まで機械で止める: 誤検出が多く、許可が広がって骨抜きになる
- グローバルな git フックで全リポジトリに効かせる: このマシンの外では効かず、仕組みも別に要る（スコープ外）

## 4. 影響

- 既存ファイルに見出しのヒットがある間は、dotfiles の `.pre-commit-config.yaml` へ点検を登録できない
  （`pre-commit run --all-files` と `master` 向きの CI が落ちる）。登録は既存ファイルを直した後に行う
- 配った先に既存の見出しのヒットがあれば、そのリポジトリで直す
