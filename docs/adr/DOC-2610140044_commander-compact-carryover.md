# ADR: 司令官の自己 compact を見送ったら、保留の印を置いて次の静かな時点で再判断する

## ステータス

決定（2026-10-14）。ADR DOC-2610130913 の「区切りで1回だけ判断する」部分を補う。区切りの定義・除外条件・閾値は変えない。

## 1. 背景

ADR DOC-2610130913 は、孫をマージした後の区切りで司令官が自己 compact すると決めた。実ログ（2026-10-13 13:53 JST の
配布以降）では、司令官の compact のうち自発的なものは一部で、他の2件は人間に促されてからだった。

- 見送りの1件目の原因: 孫のマージ直後に計画書を更新して人間へ質問を投げ、並行する孫の報告も続々と届いていた。
  スキルは除外条件（人間への質問の返答待ち・孫の報告待ち・未処理の報告）に従い見送ったが、見送った後に
  判断し直す場面が無く、そのまま忘れた。
- 見送りの2件目の原因: transcript を確かめると、マージは人間の「OK」への返答として行われていた（孫の報告や
  cron の巡回経由ではない）。マージ後は傘ブランチでの lint・テスト、計画書の更新、孫への連絡、人間への報告と続き、
  3つの判断点（§3.3・§3.5 cron 手順8・§3.6 手順4）のどこにも届かなかった。1件目と原因は別だが、
  「判断の機会が1回しか無く、外れたら次が無い」点は同じである。

並行する孫が多く人間とのやり取りが多い傘ほど、静かな区切りは来にくい。

## 2. 決定

1. 見送ったとき（150,000 超だが除外条件に当たった）は、**保留の印**を置く。
2. 印があるあいだ、巡回 cron の各 tick の最後（何もしない tick でも）と、人間の返答を処理し終えた最後に、
   手順1から判断し直す。まだ除外条件に当たれば印を残し、150,000 以下なら消す。compact したら復帰メモと一緒に消す。
3. 印は復帰メモと同じリポ外のディレクトリ（スクラッチパッドか `mktemp -d`）の `compact-pending` ファイル。
   **計画書には書かない。**

## 3. 理由と却下した案

- **区切りで毎回、機械的に強制する**: 人間は、切る時点を機械的に決めると文脈の保持が悪化することを心配している。
  切ってよい時点を司令官が選ぶ原則は残し、選び直す機会だけを足した。
- **印を計画書に書く**: 計画書は孫の進捗・決定事項など本来の記録の場所であり、司令官の段取りを混ぜると
  メモ欄になる。コミットにも載る。計画書に載せるのは本来の記録だけ、とスキルに明記した。
- **印をリポ内の非追跡ファイルに置く**: 分類器に止められうるうえ、ワークツリーを汚す。復帰メモが既に
  リポ外で書き消しされ、止められていない実績があるので、同じ置き場を使う。
- **再判断を孫の報告処理や毎ターンの末尾にも置く**: スキル本文の読み込みは司令官の費用の有意な割合を占める
  （調査 DOC-2610130216）。巡回は30分ごとに必ず来るので、cron の tick と人間の返答処理の2点に絞った。
- 弱点: セッションが作り直されると印が消える。その場合は次の区切りまで従来どおりになるだけで害は無い。
