# ADR: AI が書く日本語の癖を、基準の文書・指示文・読まれる文書の書き直しで抑え、モデルの文脈判定で計測する

## ステータス

確定（2026-11-17。傘ブランチ `wording-habits` の孫2）

## 1. 背景

AI（主に Claude Code）が書く日本語には、持ち主が何度指摘しても直らない癖がある。要約すると3つある。

1. 読み手がふだん使う名前を使わず、別の言い方に置き換える（和語に開く・定着したカタカナ語を日本語にする・
   定着していないカタカナ語を押し通す・直訳の造語・比喩のラベル・同じ物事の呼び分け）
2. AI 特有の決まり文句で、文を埋める
3. 「この場面でその判断が悪い」という指摘を、「今後一切しない」という規則に置き換えて広げる

メモリへの記録と指示文の追記では直らなかった。孫1 は、例の語を正規表現で数えて `Stop` hook を推奨したが、
語の適否は文脈で決まるので、その方法は取り下げた（調査結果
[DOC-2611172119](../reference/DOC-2611172119_言葉の悪癖を抑える仕組みの調査結果.md) §6）。

## 2. 決めたこと

1. **基準の文書を作る。** 3つの癖のそれぞれについて、目標・理由・境界・良い例と悪い例を書く。基準は向きを持たない
   （和語か漢語かカタカナかでなく、「読み手がその文脈で実際に使う名前か」）。例は対象の全部ではない。
   [DOC-2611172307](../design/DOC-2611172307_AIが書く文章の言葉.md)
2. **基準の要点を `claude/CLAUDE.md` の指示文にする。** 配布先の3エージェント（Claude Code・Codex・OpenCode）へ届く。
   基準の文書のパスは他のマシン・他のリポから読めないので、要点は本文に書く。向きを持った既存の規則
   （プルリクエストの作法 DOC-2608020715 と `templates/repo-baseline/` の写しの「平易な言葉を使う」「横文字を避ける」）は、
   向きを持たない書き方に修正した
3. **AI が毎回・頻繁に読む文書そのものを、基準に沿った文体へ書き直す**（この ADR の後続の孫が行う）。指示文の文体は
   出力の文体に影響するので、今の文体で書かれたスキル・指示文がお手本になっている可能性が高い。対象は、読まれた回数の
   累積で8割程度を占めるファイルとし、ADR と終わった傘の計画書は含めない
4. **効果はモデルが文脈で判定して計測する。** 過去の返事から無作為に抜き、基準の文書をそのまま判定の基準に渡して、
   3つの癖への該当をモデル（Haiku）に判定させ、割合を基準値にする。導入後に同じ引数で期間だけ変えて比べる。
   スクリプトは `docs/adr/probes/wording-habits/` の `wh_judge.py`（判定）と `wh_freq.py`（読まれる頻度）。値は
   調査結果 [DOC-2611172119](../reference/DOC-2611172119_言葉の悪癖を抑える仕組みの調査結果.md) §9

## 3. 採らなかった案と理由

| 案 | 採らなかった理由 |
|---|---|
| 正規表現の `Stop` hook | 語の適否は文脈で決まる。例の語を増やしても例以外に効かず、普通の用法を止める誤りが増える（DOC-2611172119 §6） |
| 語のリスト（禁止語・言い換え表）を指示文に置く | 公式ガイドは「するな」より「何をするか」と理由を勧める。禁止語を名指しするとかえって出やすくなる報告もある（DOC-2611172119 §7）。リストは例の分しか効かず、向きの規則が広がって定着語まで開く原因になる |
| 計測に正規表現の値を使う | 同上。値は例の語の出現の目安にだけ使う |
| 毎ターンの再注入（`UserPromptSubmit` の hook） | 長い会話ほど文脈を圧迫し（DOC-2611172119 §8）、効果は計算できない。**書き直しの後に、長い会話で癖が残るかを見てから判断する**（この ADR では採否を決めない）。実施するなら、前回から文脈が一定量増えたときだけ注入する |
| 人格（`CLAUDE.machine.md`）の変更 | 持ち主のもので、この傘のスコープ外。メモリへの書き込みでも癖が同程度に出ているので、人格が主因とは考えにくい |

## 4. Codex・OpenCode に届くもの

- `claude/CLAUDE.md` の追記は、`codex/deploy.sh`（連結生成）と `opencode/deploy.sh`（symlink）を通じて3エージェントへ届く
  （ADR DOC-2609072334・DOC-2609162327）
- 基準の文書・プルリクエストの作法・計測スクリプトは、このリポジトリで作業する AI に届く（`AGENTS.md` の「作業別の索引」から読む）
- hook は採らなかったので、Claude Code 固有の仕組みは増えていない

## 5. 結果の見方

- 導入前の基準値と読まれる頻度は DOC-2611172119 §9。書き直しの後に同じ引数で計測し直し、基準値からの差を見る
- 判定の妥当性は、約20件の抜粋を持ち主が見て、判定が持ち主の感覚と合っているかで確認する（抜粋は会話の本文を含むのでリポの外）
- 効果が出ない場合の次の手: 毎ターンの再注入、判定をモデルに任せる `Stop` hook（毎ターンの費用と遅延が乗る）
