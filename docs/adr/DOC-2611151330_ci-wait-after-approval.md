# ADR: 承認と CI を切り離し、CI はマージの前に司令官が見張る

## ステータス

決定（2026-11-15）。

## 1. 背景

ある private リポで、傘ブランチの孫の PR がレビュー1往復ごとに約15分の CI を待ち、その待ちが孫の数だけ直列に
積み上がっていた。原因は2つ。

- `pr-review-loop` が「CI が現HEADで green」を full suite の一番強い証拠にして、push のたびにそれを待ってから
  承認・再レビューする
- 司令官（`umbrella-orchestrator`）が孫を依存どおり1本ずつ spawn しがちで、孫の CI 待ちがそのまま直列に積まれる

加えて、そのリポは孫 PR の CI で流す範囲を絞る方向（全件は傘→既定ブランチと既定ブランチで流す）にあり、
孫 PR の「CI が green」は全件の証拠でなくなる。

## 2. 決定

### 2.1 承認の前の CI 待ちを、リポ側の宣言で外せるようにする（`ci_gate: after_approval`）

- `.claude/pr-review.yml` の `ci_gate: after_approval` を宣言したリポで、**base が既定ブランチでなく、
  かつ司令官のペインが渡されている PR**（傘ブランチ向きの孫 PR）に限り、レビュワーは CI の完了を待たずに承認してよい
- **CI が現HEADで赤なら承認しない**は残す。pending は承認してよい
- 宣言が無いリポ、base が既定ブランチの PR、司令官のペインが渡されていない PR
  （マージ前に CI を確かめる人がいない）は従来どおり（CI green を承認前に確認する）。黙って弱くならない
- 孫の実装AI は承認の時点で司令官へ報告する（CI を待たない）

### 2.2 CI を待つ場所を、承認の前から司令官のマージの前へ移す

- `umbrella-orchestrator` §2.4 のマージ条件に「対象HEAD の必須チェックが green」を足す
- 実行中なら司令官はバックグラウンドで見張り（`gh pr checks --watch` の `run_in_background`・`Monitor`・巡回）、
  green でマージ。赤なら孫に戻す。見張っているあいだは止まらず、次の孫を進める
- 傘ブランチ向きの孫 PR には必須チェックの設定が無いことが多く、`gh pr checks --required` は
  「必須なし」を失敗と同じ終了コードで返す。そのため「必須があれば必須、無ければ全チェック」で読む

### 2.3 依存の無い孫は前の孫の待ちのあいだに spawn する

「依存:」に書かれていない孫は、前の孫の CI 待ち・レビュー待ち・マージ待ちのあいだに spawn してよい。
歯止めは、同時に動かす数の目安（3）と、同じファイルを触りそうな孫を並べないこと。

### 2.4 絞った CI の宣言（`child_pr_ci: narrowed`）

孫 PR の CI を絞るリポは、`child_pr_ci: narrowed` を宣言する。宣言があれば、base が既定ブランチでない PR の
「CI が現HEADで green」は絞った範囲の green で証拠として足り、全件は傘→既定ブランチの CI で確かめる。
承認文にその旨を書かせる。`ci_gate` とは独立した宣言。

## 3. 却下した案

| 案 | 却下の理由 |
|---|---|
| CI を待つのをやめる（宣言なしで全リポ一律） | CI が赤い・まだ走っている HEAD を、誰も確かめないままマージしうる。宣言したリポだけ、かつ傘向きの PR だけに限り、確認をマージの前へ移す形にした |
| 孫の PR で CI の green を待ち続ける（現状維持） | 待ちが孫の数だけ直列に積み上がる。人間も司令官も CI に縛られる |
| 宣言を `AGENTS.md` の決まった書式にする | `pr-review-loop` は設定を `.claude/pr-review.yml` から読む構造で、ui-review の入口もそこにある（DOC-2611040233）。文章の書式を解釈させるより、キーのほうが読み違えにくい |
| base に関わらず `after_approval` を効かせる | 既定ブランチ向きの PR のマージは人間で、司令官のような CI の関門が無い |
| 並列 spawn の上限を決めない | レビュー・フィードバックの量とマシンの負荷が追いつかず、衝突の rebase が CI の待ちより高くつく |

## 4. 影響

- `pr-review-loop`: `.claude/pr-review.yml` に `ci_gate` / `child_pr_ci` を追加（省略可）。承認の条件・完了報告・
  レビュー依頼のテンプレートに `CI_POLICY` を追加
- `umbrella-orchestrator`: §2.4（マージ条件・CI の確認・赤の戻し方）、§3.5（依存の無い孫を先に進める・巡回の手順）、
  §3.6（承認の時点で報告・CI 待ちの見張り）、状態に `⏳ CI待ち` を追加
- 宣言を足すかどうかは各リポが決める。足したリポで、孫 PR の CI を絞る仕組みを入れる作業は各リポ側の仕事
