# ADR: ocw-meter report の表示を人間向けの pretty 表示にし、既定にする

## ステータス

決定（2026-10-31）。傘 `ocw-meter-pretty-charts`（計画書 DOC-2610312019）の孫1 で決めた。実装は `bin/ocw-meter` の
「pretty 表示の部品」の区画と `report` の各ビュー、使い方は [bin/README.md](../../bin/README.md)。

## 1. 背景

`ocw-meter report` の出力は YAML 風の `key: value` の羅列で、AI に読ませるぶんには困らないが、人間には読みにくい。数字に桁区切りが無く、
cache_read が 251 億トークンのように桁が大きいと、どれが大きいのか一目で分からない。診断行（completeness / attribution / price_table /
ingest の鮮度など）が本体と同じ見た目で並び、本体の数字に埋もれる。人間が決めた方針は「人間向けの pretty 表示を作り、`report` の既定に
する。出力先は端末」である。以降の孫（日ごとのグラフ・週の上限の推移・ヒートマップ）も同じ部品に乗る。

## 2. 決定

1. **標準ライブラリだけで描く。** `bin/ocw-meter` は 1 ファイルを symlink で各マシン（macOS / Linux / WSL2）へ配るもので、外部依存が無い。
   `rich` などを足すとマシンごとにインストールが要り、入っていないマシンで `report` が動かなくなる（`report` の fail-open に反する）。
   描画の部品（表・横棒・色・数値の整形・東アジアの文字幅）は `bin/ocw-meter` の Python 本体の中に、まとまった 1 区画として置く
2. **出力のモードは 3 つ。** 既定は pretty（人間向け）、`--plain` は従来の `key: value`（AI・スクリプト向け）、`--json` は従来の JSON。
   `--plain` と `--json` を同時に付けたらエラーにする。`--plain` の経路は従来のテキスト出力の関数をそのまま残して使い、書き直さない
   （変わっていないことが差分で一目で分かる）。`--json` は変えない
3. **端末でなくても pretty のまま出し、色だけを落とす。** 「既定は pretty」という決定を、端末かどうかで変えない。AI やスクリプトが
   読むなら `--plain` か `--json` を付ける。ファイルへ残して後から機械で読み比べる手順は `--plain` を付ける形に直した
4. **色の条件。** 色は、標準出力が端末（`isatty()`）で、かつ環境変数 `NO_COLOR` が空でない値で立っていないときだけ出す（no-color.org の
   約束）。色を強制するフラグは足さない（要るとなったら別件）。色が無くても読めるようにする（系列は記号・凡例の順、濃淡は記号で区別し、
   色は補助にとどめる）。色はモデル系統・警告など意味のある所にだけ使う
5. **幅。** 端末幅は `COLUMNS` を尊重し（`shutil.get_terminal_size()`）、取れなければ 80。ラベルは表示幅（全角は 2）で揃える。入りきらない
   ときは表の右端の列から落とし、落とした列を 1 行で添える（崩さない）。長くなる表（`--window` は数百行）は新しい順に絞り、省略した件数を添える
6. **数値。** 件数は桁区切り（`281,234`）、トークンは表では `K` / `M` / `B` に丸める（`25.1B` `340.2M` `12.3K`。1,000 未満はそのまま。
   丸めで `1000.0K` にならないよう次の単位へ送る）、費用は `$` と小数 2 桁。正確な値は `--plain` と `--json` で取れる
7. **診断行は末尾の「注記」欄にまとめる。ただし警告は落とさず目立たせる。** ingest の鮮度の警告・ingest の失敗・未隔離の不正行・隔離済みの行・
   価格表のフォールバックは、色付き（色なしでも `⚠` が付く）で注記の先頭に出す。それ以外の診断（completeness・coverage・cost・attribution・
   ingest の概要）は短い key/value で並べ、全文（価格表の説明、数え漏れの条件の文章など）は `--plain` で見られる旨を添える
8. **見積もれない値は `—` にして理由を添える。** `--quota-per-pct` で測れない系統は数値の欄を `—` にし、理由を表の下に出す
9. **一画面のダッシュボードは `report` のフラグではなく独立のサブコマンド `ocw-meter dash` にする（新しいビューは `report` のフラグ、という
   原則の例外）。** 打ちやすさを人間が優先した。個別のビュー（`report --daily` など）はそのまま残す。`dash` は人間向けの表示だけを持つので
   `--json` / `--plain` は付けられない（エラー。機械が読むなら個別のビューを使う）。`report` と同じく先頭で ingest し（`--no-ingest` で飛ばせる）、
   ingest の失敗は止めずに注記へ出す。各グラフは `--quota-progress` / `--daily` / `--heatmap` の描画の部品に高さと幅を渡して呼び、書き直さない。
   端末の高さに収まるよう、まずグラフの高さを詰め、それでも足りなければヒートマップ → 日ごとの縦棒の順に省いて、省いたことを 1 行出す
   （高さが取れない＝パイプ・ファイルのときは詰めない）。**`--watch [秒]` の約束:** 既定 300 秒ごとに ingest して描き直す。ANSI のエスケープで
   画面を消してから描く（`curses` は使わない）。待ち時間は描き終わってから数えるので、ingest が間隔より長くかかっても重ならない。ingest が失敗しても
   保存済みの集計で描き、注記に出す。ファイルへ延々と書き続けないよう、端末でないときの `--watch` はエラーにする。Ctrl-C は終了コード 0 で抜ける
10. **`dash` は全体を枠付きのパネルで組む（孫8）。** 見た目が「文を並べただけ」でまとまりに欠けるとの評価を受けた。見出し・週の上限・日ごと・
    ヒートマップ・注記を、端末幅いっぱいの同じ幅の角丸の枠（`╭╮╰╯─│`）で囲み、タイトルを上の罫線の左、補足（凡例・期間・単位）を右に埋め込む。
    見出しは数字のタイル（ラベルと値の 2 段）で、入らなければ優先順位の低いタイルから外す（値は切らない）。使用率は 70% / 90% で緑・黄・赤。
    **全グラフの縦軸のラベルの欄は同じ幅（最大のラベルに合わせる）で右寄せし、軸の線を同じ列に置く。** 高さの省き方（上の 9）は変えず、
    省いたことは見出しのパネルへ、警告は最下部の注記のパネルへ出す。個別のビュー（`report --daily` など）の見た目は変えない。

## 3. 却下した案

- **`rich` などの描画ライブラリを足す。** 上記 1 のとおり、入っていないマシンで `report` が動かなくなる。自前の描画は表・横棒・色だけで足り、量も小さい
- **端末でないときは旧形式に戻す。** 「既定は pretty」という人間の決定を端末かどうかで変えることになり、`report > file` で得られる内容が文脈で変わる。
  色だけを落とせば足りる
- **旧形式を消す。** 既存の文書とテストが機械で読み比べる用途で旧形式に依存している。`--plain` で残す方が、AI の読み取りも壊さない
- **`--color` で色を強制するフラグ。** 今は要る場面が無い。要るとなった時点で別件として足す

## 4. テストの考え方

描画の結果を丸ごと文字列で固定するテスト（スナップショット）は作らない。端末幅や記号の細かい調整のたびに壊れ、守る価値が薄い。守るのは振る舞い
（端末でない出力・`NO_COLOR` で色コードが混ざらない、端末では色が出る、`--plain` が従来の出力のまま、`--plain` と `--json` の同時指定がエラー、
単位の丸め）である。
