# ADR: マージ済みの孫の片付けは、司令官が人間に聞かず実行して報告する

## ステータス

決定（2026-10-14）。軽いハンドオフ（PR 1本）で決めた。

## 1. 背景

`umbrella-orchestrator` §3.3 手順5 は、マージ・検証が済んだ孫の片付けを「提案して人間の確認を取る」と
していた。人間は以前から「終わった孫は消していって」と口頭で指示しており、スキル本文と運用が食い違って
いた。また `--force` が要る場面（計画書 DOC-2609080222 背景6.1）は、AGENTS.md の「上流の取り込みは
rebase」運用では日常的に出るため、片付けのたびに承認が飛ぶ状態になっていた。

## 2. 決定

1. **マージ済み＋検証済みの孫は、司令官が人間に聞かず `ocw rm` し、報告する。** 未マージの孫は消さない
   （`ocw rm` が未マージを拒否する安全網は変えない）。
2. **人間が「孫N は残して」と言った孫は消さない。** 「マージを待て」と同じ口頭の指示として扱い、
   compact をまたいで失わないよう、計画書ではなく復帰メモ（§3.7）に持つ。
3. **`--force` は、次の3条件が全部そろえば承認なしで使ってよい。** 1つでも外れたら従来どおり人間に聞く。
   DOC-2609080222 背景6.1 の「人間の承認」を機械的な確認に置き換えるもの。
   - `gh pr list --head <branch> --state merged` で PR がマージ済み。
   - 手元の孫ブランチ先頭が PR の `headRefOid` と一致（未 push のコミットが無い）。
   - 孫のワークツリーに未コミットの変更が無い。
4. **報告に孫のセッション ID を添える。** 消す前に `agent_session.value` を控える（`ocw rm` でペインが
   消えると引けない）。後で話を聞きたくなったら `claude --resume` で戻れる。
5. auto mode の分類器が `-f` を止めたら回避せず、`PushNotification` で人間に知らせて次へ進む。

## 3. 前提の確認

ワークツリーを消した後でも `claude --resume <ID>` で会話に戻れるかを、捨てて良い一時ワークツリーで
確かめた（2026-10-14）。作業ディレクトリを `rm -rf` した後、別ディレクトリからも、ディレクトリを
作り直してからも、会話の内容を引き継げた。

## 4. 却下した案

- **`ocw rm` に3条件を確かめる `-f` 相当のオプションを足す。** 安全網をコードに持てる利点はあるが、
  `bin/ocw` とそのテストの変更が要り、1本の運用変更としては大きい。3条件は `gh` と `git` の
  素のコマンドで確かめられるので、スキル本文の手順に留めた（本文の膨張は条件3行に抑えた）。
  必要が出たら別の件で検討する。

## 5. 影響

- `skills/umbrella-orchestrator/SKILL.md` の §3.3 手順5・補足、`--force` に触れる §3.2 の注意書き、
  §3.7 の復帰メモの項目。
- `skills/worktree-cleanup`（司令官の終了後の掃除）は対象外で、人間の承認を取る作法のまま。
