# ADR: 孫ごとのレビューは省かず、nit では止めず、文書だけの PR は見る範囲を絞る

## ステータス

確定（2026-10-14）。傘 `review-tiering`（計画書 DOC-2610140002）の孫4 で反映した。決めたのは人間で、
根拠は過去データの分析と再現実験の結果（DOC-2610140007 の §5.2 と §9）。

## 1. 背景

孫の PR 1本ごとに `pr-review-loop` でレビューをかけていたが、PR の種類にかかわらず同じ厚さだった。
DOC-2610140007 の分析（再掲を除く指摘 976 件）で次が分かった。

- D2（`pr-review-loop` の gate を通らない nit）は指摘の 17% を占め、後続の孫に響いた例は 0 件。
  それでも 166 件がそのまま直されており、nit を直すためのラウンドが回っていた
- 文書だけの PR では A（実害のあるバグ）は 1%。一方で PR の 41% に A か B が付き、B は後続の孫に
  響きやすい（波及 24%）。指摘の 60% は D1（文書を信じた人が誤操作しうる不整合）だった
- 土台・実装コードの PR は A を含む割合が高く（89% / 75%）、弱いモデルの実装は 91%。
  孫ごとのレビューを薄くする根拠は出なかった
- 「傘の最後に1回だけ」のレビューでは、孫レビューが止めた A/B/C のうち拾えたのは 11%（partial を
  足して 15%）にとどまった（DOC-2610140007 §9）

## 2. 決定

1. **D2 はレビューを止める理由にしない。** 書くなら承認コメントの末尾に「任意」と明記して添える。
   修正要求ではないので「1レビュー1判定」の未解決指摘に数えず、実装者は直さなくてよい。
   孫 PR のレビューにも傘→既定ブランチの最終レビューにも当てはまる。gate（`pr-review-loop`
   「finding の判定基準」）は元から nit を finding にしなかったが、「投稿しない」とだけ書いてあり
   承認コメントに添えてよいかが読み取れなかったため、書き方を直した
2. **傘ブランチへ向く文書だけの孫 PR は、レビューを省かずに見る範囲を絞る。** 見るのは B（計画書・他の孫・既存の契約との
   食い違い）と D1 だけ。「文書だけ」の判定は DOC-2610140007 §3 に従い、判断がつかなければ文書だけと
   しない。finding と認定したものの扱い（全件 blocking）は変えない

変えないもの: 土台・実装コード・小さい PR の孫レビューの厚さ、傘→既定ブランチの最終レビューと傘の外の PR（絞るのは孫 PR だけ）、実装役のモデルによるしきい。

## 3. 反映先

- `skills/pr-review-loop/SKILL.md`: 「finding の判定基準」の pure nit の扱い、新しい小節
  「文書だけの PR のレビュー範囲」、レビュー指示テンプレートの nit の1行。gate の節は
  レビュー指示へそのまま貼られるので、実装者の自己レビューとレビュワーの両方に効く
- `skills/umbrella-orchestrator/SKILL.md`: 孫のプロンプトの節に、孫ごとのレビューを省かない旨の2行
- risk-based なテスト方針の3箇所（`pr-review-loop`・`templates/repo-baseline/template/AGENTS.md.jinja`・
  `AGENTS.md`）は、テスト不足の判定基準を変えていないので触らない（確認済み）

## 4. 却下した案

- **「傘の最後に1回だけ」のレビューへ置き換える**: 上記の 11% / 15% のため。今回は扱わない
- **叩き台にあった「小さい PR のレビューを省く」「実装役のモデルでしきいを変える」**: 人間が決めなかった
  （小さい PR は抜き取りが 11 本で判断できない。弱いモデルは今のままで十分厚い）

## 5. 効果の測り方

運用を変えたあとの孫 PR のラウンド数と、役割別（実装・レビュー・司令官）の費用を、傘ごとに比べる。
費用は `python3 -I docs/adr/probes/usage-diet/by_unit.py [<リポ>:]<傘ブランチ> ...` が1コマンドで出す
（孫2 の成果。`ocw-meter report --role` は役割の割り当てが当てにならないので使わない）。
ラウンド数と指摘の内訳は `docs/adr/probes/review-tiering/` のスクリプトで DOC-2610140007 と同じ基準で出せる。
見るのは、D2 だけを理由にしたラウンドが減ったか、文書だけの PR で B / D1 の取りこぼしが出ていないか。
