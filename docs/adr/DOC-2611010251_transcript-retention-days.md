# ADR: Claude Code の transcript の保持期間（`cleanupPeriodDays`）を 90 日にする

## ステータス

決定（2026-11-01）。傘 `meter-ingest-retention`（計画書 DOC-2611010249）の孫1 で決めた。

## 1. 背景: 記録が欠落した仕組み

`ocw-meter` の使用量の記録（`usage.message`）は、Claude Code の transcript
（`~/.claude/projects/*/*.jsonl`）を `ingest` して初めて作られる。`ingest` が走るのは、手で
叩いたときと `report` / `dash` の先頭だけで、定期的に走る仕組みは無い。一方 Claude Code は既定で
30 日より古い transcript を消す。この2つが重なり、2026-08-06〜09-04 の 30 日間の使用量が
永久に失われた（他のイベントは hook・statusLine から直接書かれるので残っていた）。

## 2. 決定

`claude/settings.json` に `"cleanupPeriodDays": 90` を足す。

### 2.1 この設定の役目は「保険」

再発防止の本体は孫2 の自動の取り込み（statusLine 起点）で、Claude Code を使っている間は
transcript が消える前に拾う。この設定が埋めるのはその届かない隙間である。最後の取り込みの後に
少し使い、その後長く Claude Code を開かなかった場合、次の起動時の掃除（Claude Code は起動時に
古い transcript を消す）が取り込みより先に走り、最後の少しを失いうる。保持期間が「長く使わない
期間」より長ければ、この隙間は塞がる。孫3 の警告は孫2 が壊れたときの見張りで、守りは三段になる。

### 2.2 90 日にした理由（ディスク使用量の実測）

このマシン（2026-11-01 の実測）の `~/.claude/projects` は 2,213 本・約 14 GB。最終更新の月別は
10 月が約 14.1 GB（2,011 本）で、**1 か月あたり約 14 GB 増える**。ホームのディスクは
1,007 GB 中 567 GB 空き。

| 値 | 定常状態の使用量（概算） | 評価 |
|---|---|---|
| 30（既定） | 約 14 GB | 欠落が起きた設定。保険にならない |
| **90** | **約 42 GB** | **採用。3 か月は「長く使わない期間」として十分で、空きの 1 割未満** |
| 180 | 約 85 GB | 空きの 15%。保険としては過剰 |
| 365 | 約 170 GB | 空きの 3 割。1 年空けて戻る使い方は想定しない |

使用量は線形に増えるので、値は使用量にそのまま比例する。90 日はこのマシンでの許容と、隙間を
塞ぐのに要る長さの釣り合いで選んだ。取り込みが正常なら保持期間は欠落に効かないので、長くして
得られる安全は逓減する。

## 3. 0 を使わない理由と出典

公式文書（Claude Code の claude-directory「Cleaned up automatically」節、2026-11-01 確認）に
よれば、`cleanupPeriodDays` より古いファイルが掃除の対象で、**既定は 30 日、最小は 1、`0` を
設定すると検証エラーになる**。上限の記載は無い。数え方の基準（最終更新か作成か）も文書には
明記が無いので、このリポジトリは基準に依存した設計にしていない。0 や負の値は使わない。

掃除の対象は transcript だけではなく、サブエージェントの transcript・`tool-results/`・
`file-history/` なども同じ期間で消える。期間を延ばすとこれらも同じだけ残る（上の使用量は
`projects/` のみの実測）。Claude Desktop / Cowork の transcript は既定で掃除の対象外。

## 4. マシンごとの上書き

`claude/settings.json` は全マシンに配られるベース設定で、`claude/deploy.sh` が
`settings.machine.json`（マシンローカルの固定パス実体）とマージして `~/.claude/settings.json` を
生成する。ディスクに余裕の無いマシンは `settings.machine.json` に
`"cleanupPeriodDays": <日数>` を書けば上書きできる。配るのは人間の `deploy-all.sh` で、
マージ後に効く。

## 5. 却下した案

- **365 日**: 使用量が 170 GB 前後になり、隙間を塞ぐという役目に対して過剰。
- **0 で保存を止める／掃除を止める**: `0` は検証エラー（§3）。仮に通っても、取り込み前の
  transcript を残すという目的と逆になる。
- **OS のスケジューラで定期 ingest**: 計画書 DOC-2611010249 の設計2 で却下済み。
