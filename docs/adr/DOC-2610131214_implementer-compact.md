# ADR: 実装の孫はレビューを依頼した直後の区切りで自分を compact する

## ステータス

決定（2026-10-13）。傘 `usage-diet`（計画書 DOC-2610122205）の孫5 で決めた。専用コマンドと allow ルールが
本番で分類器に勝つかは ADR DOC-2610130913 §6 の未検証のままで、勝たなければこの手順は何もしない形に落ちる。

## 1. 背景

調査 DOC-2610130216 §3.4 で、実装の孫は費用の 53% が文脈 20万超の呼び出しだった。上限を超えたら 80k まで
縮めるとして compact のコストを引いた純削減は、実装で C=150k が 10%、C=200k が 13%、C=300k が 8%
だった。人間はこれを孫5 にすると決めた（計画書 設計4）。手段は孫4 の専用コマンド `ocw self-compact` と
許可ルール `Bash(ocw self-compact *)`（ADR DOC-2610130913）で、新しい機構は足さない。

## 2. 決定

1. **区切りは2つだけ**: PR を出してレビューを依頼した直後（`pr-review-loop` Phase 2 Step 4 のあと）と、
   指摘対応を push して再レビューを依頼した直後（Phase 6 手順5のあと）。実装・修正の途中、Phase 7
   （承認後）、レビュワーでは行わない。実装の途中で compact すると作業中の判断が落ちる（調査の注意）。
   承認後は残る仕事が少ない。レビュワーは文脈が 20万に届かず、試算では C=150k で −12%、C=200k で −2% の損になる
2. **閾値は 200,000 トークン**。文脈がこれを超えているときだけ行う。測り方は司令官（SKILL.md §3.7）と同じ
   （セッションログの直近の assistant の使用量の合計）
3. **復帰メモ**: リポ外のファイルに書き、先頭に「次は Phase 3（レビュワーの完了待ち）に戻る。依頼は
   再送しない」と書く。続きに要る値（PR・`$ROUND`〔Phase 6 からなら繰り上げ後の値〕・`$HEAD_SHA`〔同、差し替え後〕・`$REVIEWER_PANE`・`$REVIEW_REQUEST` のパス・
   設定・計画書の場所・司令官のペイン ID）も入れる。待っていたレビューは、復帰後に `herdr pane get` で
   状態を見て、`working` なら `herdr agent wait`、`idle`/`done` なら GitHub の投稿を収集する。完了通知は
   来ないので、compact の間に投稿されたレビューも GitHub から拾える
4. **使えないときは何もしない**: コマンドが無い・拒否された・失敗した・Claude Code 以外のエージェントなら、
   そのまま Phase 3 へ進む。司令官と違い、人間に提案も通知もしない（人間の手を煩わせる価値が小さい）。
   拒否は回避せず、同じ区切りで繰り返さない
5. **コマンドは変えない**。続きを促す固定文は「復帰メモがあれば読み、計画書の続きから再開してください。」で
   孫にも通じる。メモの先頭に「メモの指示に従う」と書くことで、計画書とメモが食い違わない

## 3. 閾値を 200k にした理由

- 試算の純削減は 200k が最大（13%、44回）。150k は 98 回で 10%（1回あたりの得が薄い）、300k は 12 回で 8%
- 実装は1 PR ごとの作業で、区切りは PR 1本につき数回しか来ない。高い閾値だと、届く前に PR が終わって
  取りこぼす。したがって試算で最大かつ回数が現実的な 200k にした
- 見積もりであり、実運用の値と、司令官側の `ocw self-compact` の本番での通過（ADR DOC-2610130913 §6）を
  確かめてから見直す

## 4. 却下した案

- **実装の途中でも閾値を超えたら compact する**: 作業中の判断が落ちる。区切りにだけ行う
- **レビュワーも compact する**: 損になる（§2.1）
- **使えないときに人間へ提案する**: 司令官は1傘に1人で区切りが少ないが、実装の孫は多数で通知が頻発する。
  人間の決定（設計4）でも提案しない
- **autocompact の閾値を下げる**: 発動のタイミングと残す内容を選べず、実装の途中で走りうる
  （ADR DOC-2610130834 §3）

## 5. 未検証

- 孫のペインで `Bash(ocw self-compact *)` が分類器に止められないか（司令官側と同じ ADR §6 の未検証）
- compact 中にレビュワーが完了した場合の復帰（GitHub の投稿を収集するため問題ない想定。実機での確認は
  運用で見る）
