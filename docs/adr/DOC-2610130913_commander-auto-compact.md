# ADR: 司令官は区切りで専用コマンドにより自分を compact する

## ステータス

決定（2026-10-13）。傘 `usage-diet`（計画書 DOC-2610122205）の孫4 で決めた。ルールが分類器に勝つかと、
続きを促す1通が compact の後に処理されるかは**未検証**で、マージ・デプロイ後に司令官が確かめる（§6）。

## 1. 背景

ADR DOC-2610130834 の実測で、herdr 経由の `/compact` はコマンドとして実行され、巡回 cron は残るが、
AI が自分のペインへ送ると auto mode の分類器が `[Tmux Self Drive]` で拒否することが分かった。
compact 後のセッションは自分からは再開しない。同 ADR §8 は、専用コマンドとそれだけを許す絞った
permission ルールを足すかを人間に預けた。人間は足す方向を選んだ（計画書 設計2.3）。

## 2. 決定

1. **専用コマンド `ocw self-compact <instruction>`** を `bin/ocw` に足す。自分のペイン
   （`$HERDR_PANE_ID`）へ `herdr agent prompt` で `/compact <instruction>` と、続きを促す固定の1通
   （「compact が終わりました。復帰メモを読み、計画書の続きから再開してください。」）を `--wait` なしで
   この順に送るだけ。
   - 宛先は `$HERDR_PANE_ID` 固定で、ペインを引数で指定する口が無い。許可ルールを通じて他のセッションを
     compact できないようにするため。`$HERDR_PANE_ID` が空（Herdr の外）なら何も送らず失敗する。
     引数が 1 個でない・空・複数行のときも何も送らない
   - 2通目の本文は固定。AI が自分のペインへ自由な本文を送れる口にしない
   - `ocw` のサブコマンドにした理由: 司令官は `ocw -H` で起動されており `ocw` は PATH にあるため、
     新しい配布先（`links_for_tool()`・`uninstall.sh`）を増やさずに済む。サブコマンドは git リポ
     に依存せず、`init_repo_context` を呼ばない
2. **allow ルール `Bash(ocw self-compact *)`** を `claude/settings.json` の `permissions.allow` に足す。
   `herdr agent prompt` 全般や `ocw *` は許さない（`herdr agent prompt` 全般を許すと、分類器が
   防ごうとしている「任意のペインへの送信」を AI に開くため）。ルールの追加は人間の決定であり、
   `master` へのマージ（人間）で最終承認される。
3. **自動化の範囲**: `skills/umbrella-orchestrator/SKILL.md` §3.7 を「提案のみ」から「区切りで自動実行」に
   変えた。区切りの定義は従来のまま（マージの検証・計画書の更新・次の孫の spawn まで済んだ時点。
   finalize 時・デッドロック対応中・人間の返答待ち・孫の報告待ちは除く。未処理の報告が無いことを
   加えた）。ADR DOC-2610130834 §5 の要点を入れた: 区切りの選び方、リポ外の復帰メモ（先頭に
   「compact 後に何をするか」）、cron の残存確認と再登録の判断、コマンドを実行したらそのターンを終える。
4. **落とし先**: コマンドが無い・拒否された・失敗した・Claude Code 以外のエージェントのときは、
   今までどおり人間に打つ1行を提案する。拒否は回避せず、同じ区切りで繰り返さない。

## 3. 毎回 compact するか、閾値を残すか

**区切りごとに毎回行い、150,000 トークン以下のときだけ行わない**にした。人間の決定は「マージしたら
自動で compact」であり、300k のように高い閾値で待つ理由は、司令官が自分で区切りを選べるように
なった今は無い。一方、小さい文脈では得をしない。

使った実測（ADR DOC-2610130834 §2.2、孫2 の自セッション1回分）:

| 項目 | 値 |
|---|---|
| compact 前の文脈 | 104,596 |
| compact 直後の会話 | 5,902（要約＋末尾3メッセージ） |
| 固定分（system・ツール定義・CLAUDE.md など。会話に足される） | 約 5 万 |
| compact 後の最初のリクエストの全入力 | 57,378（うち書き込み 29,263） |
| 所要時間 | 約 33 秒 |
| 要約呼び出しの入力 | compact 前の文脈ぶん（`preTokens`）。出力トークン数は測れていない |

考え方（単価は計画書 背景4 のもの。Opus 5.5 のキャッシュ読み $0.20/M、書き込み 5分 $5/M・1時間 $8/M）:

- **得**: 縮んだ量の分だけ、以後の毎ターンのキャッシュ読みが減る。文脈が C のとき、縮み幅は
  おおよそ C − 57k（固定分＋要約）。C = 150k なら約 93k、300k なら約 240k
- **コスト（1回）**: 要約呼び出しの入力 C ぶんの読み、要約の出力、compact 後の最初のリクエストで
  要約部分を書き込み直す費用（実測 29k）、約33秒の停止、要約で落ちる細部
- 単価の仮定しだいで損益分岐が大きく動く（読み単価だけなら100k 付近では元を取るのに30分ごとの
  巡回が何十回も要るが、キャッシュの有効時間が 5 分で巡回ごとに書き込み直しなら1〜2ターンで取れる）。
  **どちらの単価で動いているかは測れていない**ので、閾値は単価の仮定ではなく、実ログに compact を
  当てはめたシミュレーションで決めた

**閾値の根拠**: 孫3 の調査（`docs/reference/DOC-2610130216_使用量の測り方と削りどころの調査結果.md`
§3.4 の `simcap`。上限を超えたら 80k まで縮めたとして、compact のコストを引いた純削減）で、司令官は
上限 150k で約25%、200k で約27%、300k で約18% の削減だった。150k と 200k はほぼ同じ効果で、
300k は大きく劣る。本決定は「区切りで毎回」で、区切りは孫のマージの頻度でしか来ないため、
上限を高くしすぎると取りこぼす。したがって測定で純削減が確認でき、かつ回数が多い **150k** を
下限にした。これより小さい文脈（100k 付近）は、シミュレーションの対象外で効果が測れていない
うえ、縮み幅が小さい（実測の下限約57k）ので行わない。見積もりであり、実運用の値で見直す
（要約呼び出しの入出力トークンが測れたら ADR DOC-2610130834 §7 も合わせて）。人間が
「150k 以下でも毎回」を望むなら、SKILL.md §3.7 手順2の数字を外すだけでよい

200k・300k のままにしなかった理由: 過去の試算（SKILL.md §3.7 の根拠）は、200k が孫まで巻き込み、
実装途中の読み直しの取り違えの損が大きいとして司令官に限り 300k とした。区切りにだけ行う本決定では
実装途中の孫には触れないため、その損は小さい。

## 4. ADR DOC-2610130834 との関係

引き継ぐもの: §5 の要点（区切り・復帰メモ・cron の確認と再登録・ターンを終える）。補助としての
閾値引き下げ（(b)）は採否を決めず、本 ADR でも環境側の設定には触れない。

変わるもの: §4・§5-3「AI が自分で送る前提をスキルに書かない」「`herdr agent prompt "$HERDR_PANE_ID"` を
自分で送らない」は、**専用コマンド＋許可ルールを通る限り**自分で送る形に変わる。直接 `herdr agent prompt`
を打つ禁止は残る。§6 の「続きを促す入力を AI が自分のペインへ送る経路も `[Tmux Self Drive]` に当たりうる」
は、同じコマンドが2通目も送ることで対処した（ルールが勝つなら両方通る想定）。ADR DOC-2610130834 自体は
書き換えない。

## 5. 却下した案

- **`Bash(herdr agent prompt *)` を許す**: 任意のペインへ送れる口を開ける。分類器が止めている
  ものそのもの
- **ペイン指定を引数にした汎用コマンド**: 許可ルールが他セッションへの送信に流用できてしまう
- **閾値の引き下げ（(b)）だけにする**: 発動の時期と残す内容を選べず、巡回の途中やレビュー待ちの
  最中にも走りうる（ADR DOC-2610130834 §3）
- **提案のまま、人間が打つ**: 人間の決定（自動で compact）に反する。ただし落とし先として残す

## 6. 未検証と、マージ・デプロイ後の確かめ方

孫4 のセッションは、自分の許可設定を書き換えると auto mode の分類器に `[Self-Modification]` として
拒否される（プロジェクトの `.claude/settings.local.json` に仮のルールを足して試す手順が取れない）。
自ペインへの送信は `[Tmux Self Drive]` で止まる。このため次の2点は**確かめられていない**:

1. `Bash(ocw self-compact *)` の allow ルールが、`[Tmux Self Drive]` の分類器より優先されるか
2. 続きを促す1通が、`/compact` の後（compact の完了後）に処理されるか（先に処理されて
   compact の前に消費されないか、2通がまとめて1つの入力にならないか）

固定されているのはコードの契約（自ペイン以外へ送らない・Herdr の外では何も送らない・
ルールが `herdr agent prompt` 全般を許していない）で、`bin/tests/test_ocw.py` の
`SelfCompactTests` が守る。

マージ・デプロイ後に司令官が確かめる手順（実 `$HOME` へのデプロイは人間が許す手順で行う）:

1. 文脈が 150k を超える区切りで、SKILL.md §3.7 のとおり復帰メモを書いて `ocw self-compact` を実行する
2. 分類器に止められなければ (1) は成立。止められたら §3.7 手順6の落とし先（人間に1行を提案）に落ち、
   本 ADR に結果を追記して、ルールの形（例: 設定側の `ask` との兼ね合い、別の書き方）を人間と相談する
3. compact が終わったあと、2通目で復帰したかを見る。復帰しなければ (2) は不成立。その場合は
   `ocw self-compact` の2通目をやめて、人間が再開の一声をかける運用に直す（コマンドと SKILL.md の
   記述を直す）
4. compact 実行中の着信・cron の発火の扱い（ADR DOC-2610130834 §7）は、引き続き未観測として区切りの
   選び方（未処理の報告が無い時点）に頼る

## 7. 他のエージェント

`ocw self-compact`・`/compact`・`CronCreate` は Claude Code 固有。スキルは配布物なので、
§3.7 に「Claude Code の場合」であることと、他のエージェントでは飛ばす／提案に落ちることを書いた。
Codex・OpenCode の類似コマンドの有無は確かめていない。
