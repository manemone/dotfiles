# ADR: 画面を触る PR を別の目で確認する汎用スキル `ui-review`

## ステータス

決定（2026-11-04）。

## 1. 背景

画面の出来が悪く、直しに時間と費用がかかる、という問題がある。原因は次の 3 つ。

- 実装した人が自分で確認する（自己チェック）と、計画書や内部の名前の言い回しに慣れていて、不自然な字に気づけない
- 確認項目を実装役が書くと、見たいところだけを見る自己チェックに近くなる
- 全部のボタンを複数の幅で 1 つずつ押す確認は、時間も費用もかかりすぎる（1 本あたり 1 時間半・約 49 万トークンの実測があり、規模の大きいデータでは最後まで回らなかった）

そこで、実装役とは別の目が、安く（1 つの幅・流れ 1 本・30 分以内）画面を触って確認する汎用のスキルを共通のスキルのリポに置く。
特定のリポの原則・用語表・流れは、スキルには書かず、リポ側の入口から読む。

## 2. 調べた既存のもの（2026-11-04）

| もの | 使うか | 理由 |
|---|---|---|
| design-review（公開の画面レビュー一式。MIT） | 骨格だけ下敷き | 別のレビュー役・4 段の指摘（Blocker / High / Medium / Nitpick）・原則の文書を差し替える前提、は取り入れた。文は写さず書き直した。Playwright の MCP で触る前提、3 つの幅、アクセシビリティ、入力の誤りや空の状態まで見る 7 段は重すぎるので使わない |
| webapp-testing（公開のスキル集にある、Playwright のスクリプトで手元の Web アプリを確認するスキル） | 考え方だけ採用 | MCP を入れず、スクリプトを書いて画面を触る形が安い。レビュー役が同じ方針で操作スクリプトを書き、`shoot.sh` に入れる（3.5）。サーバーの起動を束ねる補助スクリプトは、入口の `serve_cmd` が受け持つので持ち込まない |
| Playwright の MCP | 使わない | 道具の説明が毎回の文脈に載り、確認役の文脈が増える。スクリプトで足りる |
| `frontend-design`、`pr-review-toolkit`（手元のプラグイン） | 使わない | 前者は見た目の設計の指針で確認の道具ではない。後者には画面を見るレビュー役が無い |
| 言い回しの辞書（textlint 系）、レイアウトの仕様検査・画面の比較（Galen・BackstopJS 系）、アクセシビリティの検査（axe-core） | 使わない | 機械で数えられるものは、各リポが入口の `machine_checks` に置く。このスキルは機械チェックの中身を持たない。全面のアクセシビリティ確認はやらないと決めた（ラベルの無いアイコンのボタンを見るのは `machine_checks` かレビューで行う） |

## 3. 決定

### 3.1 スキル `ui-review` を `skills/` に置く

新しい配布先は要らない（`skills/` の自動検出で配られる）。手順は固定の 4 段:
機械チェック → 画面の字 → 流れ 1 本 → 原則と用語表との突き合わせ。画面の字を、計画書・PR の説明・コードより先に読む
（読んだあとでは気づけないため）。幅は 1 つ（既定 1920×1080）、流れは 1 本、上限 30 分、時間とおおよそのトークンを結果に書く。
危ない操作は押さない。

### 3.2 リポ側の入口: `.claude/pr-review.yml` の `ui_review:` 1 項目が入口ファイルを指す

| 案 | 評価 |
|---|---|
| `pr-review.yml` に多数の項目を足す（却下） | `pr-review-loop` が読む設定ファイルが太り、項目の意味をそのスキルが知る必要が出る |
| `pr-review.yml` は 1 項目（パス）だけ、中身は入口ファイル（採用） | 画面の確認の細部は `ui-review` だけが知ればよい。項目が無いリポでは何も起きない |

入口ファイルの項目（`screen_paths` `machine_checks` `principles_docs` `glossary_docs` `flows` `serve_cmd` `url`
`danger_marker` `viewport`）は `skills/ui-review/references/entry-format.md` に定める。

### 3.3 `pr-review-loop` のつなぎ

- `ui_review` が空、または PR の変更ファイルが `screen_paths` のどれにも当たらないとき、レビュー依頼ファイルに画面の節を入れない
  （今までと同じ）
- 当たるときだけ、レビュー依頼ファイルに「画面の確認」の節を入れる。レビュー役が入口から流れを選ぶ。
  **実装役が書いた確認項目は使わない**（自己チェックでは足りない、という前提）

### 3.4 レビュー役のペインから確認役を呼べるようにする

`ocw checker` は実装役のペインから打つ前提だったが、コードは `HERDR_PANE_ID` と git ワークツリーだけを見ており、
レビュー役のペイン（実装役と同じワークツリーを共有する）からも動く。ただし確認役のペイン ID は
ワークツリーの git ディレクトリの `ocw-checker-pane` に 1 つだけ控える作りで、そのまま呼ぶと**実装役が使っている確認役を
使い回す**。その確認役は実装役の確認で文脈ができており、「別の目」にならない。

そこで `OCW_ROLE=reviewer` のときは `ocw-checker-pane-reviewer` に控える（実装役側の名前と挙動は変えない）。
`OCW_ROLE=reviewer` が最初から付くのは `ocw -H` と `ocw agent reviewer` で作ったペインだけで、手で分割したペインには付かない。
そのため `ui-review` と `pr-review-loop` の節は、`OCW_ROLE=reviewer ocw checker` と明示して呼ぶ形にした
（`ocw checker` に引数を足す案は、環境変数で足りるので採らなかった）。
レビュー役の確認役は実装役の確認役と別のペインになり、文脈を共有しない。
画面を触る作業は、高いモデルのレビュー役が自分でやるより確認役（既定 Sonnet）に任せるほうが安い見込みだが、
実測は別途行う（この ADR の時点では見込み）。

### 3.5 操作はレビュー役が `shoot.sh` に書き、確認役は判定する

`ocw checker` の確認役は「`shoot.sh` をそのまま実行して撮り、撮れた画像を判定する。撮り方を探し直さない」動きに
固定されている（実装役の使い方を守るため）。`ui-review` はこの契約を変えず、合わせる。流れを通す Playwright スクリプトは
レビュー役が入口の `flows` から書いて `shoot.sh` に入れる（画面は裏で立て、終わったら止める）。スクリプトは要所のスクショと
画面の字の一覧を出し、確認役は画像と字の一覧を項目ごとに OK / NG で判定する（NG の項目だけ 4 段の段階を足す）。
`checker_prompt` は変えない。

## 3.6 追記（2026-11-04）: 答えの分かっている画面で試した結果を受けた直し

架空の確認ではなく、実在の画面を直す前の版で、持ち主の指摘 12 件を答えにして `ui-review` を回した。
拾えたのは 4 件、一部が 3 件、拾えなかったのが 5 件だった。拾えなかった理由は 2 種類あった。

- **観点が足りない。** 「押すまで中身の分からないボタン」は手順 3 に「無意味なボタン」としてあったが、
  「見たい中身が押さずに見えるか」「追加が効く範囲のそばにあるか（区切りごとか）」「字よりアイコンで足りるか」は無かった。
  どのリポの画面にも当たる種類なので、手順 3 に短い問いとして足した（段階の目安付き）。入口の流れに書かれる
  リポ固有の中身（どの画面で何が見えるべきか）は、引き続き入口に置く。観点を増やしても流れ 1 本・1 つの幅・30 分は変えない
- **画面に出なかった。** 特定の状態でだけ出るボタンは、小さいコピーの偽の相手が答えを返さないと出ない。
  出なかった部品を OK にせず「見えなかった」と書く決まりを足した。固定の答えを返す偽の相手は入口側の仕事で、スキルでは持たない

手順の詰まり: レビュー役は `ocw checker` を使わず自分で撮った。契約（`shoot.sh` と `checklist.md` を整える）が、
短い流れでは撮るより重いためと読める。確認役に渡す形そのものは変えず、短い流れ・回し直し・使えない環境では
レビュー役が自分で回してよい道を正式に書いた（使わなかった旨と理由を結果に 1 行書く）。判定の観点は同じに保つ。

## 4. 影響

- 入口の項目が無いリポの `pr-review-loop` の振る舞いは変わらない
- 画面を触らない PR では `ui-review` は回らない
- 公開リポのため、スキル・文書・コミットに、特定のリポの文書番号・画面の言葉・パスを書かない
