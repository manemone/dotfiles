# 言葉の悪癖を抑える仕組みの調査結果

AI の会話の言葉に出る2つの悪癖（和語に開いた言い換え、全面禁止の宣言）について、
**計測する方法と現状の値**、**抑える仕組みの候補ごとの効果・副作用**、**推奨案**を残す文書である。
傘ブランチ `wording-habits` の孫1 の成果で、計画書は DOC-2611172104（傘が閉じたあとは歴史的記録）。
決定はしない。どの案を入れるかは持ち主が選び、導入は孫2 が行う。

このリポジトリは公開リポジトリなので、会話の本文・人間の発言・他のリポジトリの名前は書かない。
集計値と、計画書に既に出ている語だけを書く。

## 1. 2つの悪癖の定義（計画書 背景2 の要約）

- **悪癖1**: ふだん漢語・カタカナ語で言う物事を、わざわざ和語に開いて言い換える
  （確認→確かめ、修正→直し、計測→測り、切り分け→割り出し、キャッシュ→控え、コピー→写し、
  説明の無い造語）。普通に通じる和語（引く・探す・立てる・止める・回す）は問題ない
- **悪癖2**: 「この場面でその判断が悪い」という指摘を、以後の全面禁止の宣言に広げる

## 2. 計測方法

集計スクリプトは `docs/adr/probes/wording-habits/wh.py`。孫2 の前後比較にそのまま使う。

```bash
# 週別（悪癖1・2 の件数）。期間は ISO 8601 で渡す
python3 docs/adr/probes/wording-habits/wh.py --since 2026-10-20 --by week --exclude-project 'wording|wh-0'
# 語別の件数と、開いた語の直前・直後1文字の分布（正規表現の誤検出の点検用）
python3 docs/adr/probes/wording-habits/wh.py --since 2026-10-20 --by word --ctx --exclude-project 'wording|wh-0'
# 系統別（text・final・send・memory・herdr・gh）。final は各ターンの最後の本文
python3 docs/adr/probes/wording-habits/wh.py --since 2026-10-20 --by channel --channel text,final,send,memory,herdr,gh
```

- 入力は `~/.claude/projects/*/*.jsonl` の assistant の発言。次の6系統を分けて数える。全体で約20GBあり、全期間の走査は10分前後かかる
  - `text`: 返事の本文のブロックすべて（ツール呼び出しの合間の本文も含む。持ち主には表示される）
  - `final`: **各ターン（人間の入力から次の入力まで）の最後の本文**。Stop hook が点検できる範囲に当たる
  - `send`: `SendMessage` の本文。`memory`: `/memory/` 配下への Write・Edit の本文
  - `herdr`: `herdr agent prompt`・`herdr pane run`・`herdr pane send-text` を打つ Bash のコマンド全体
  - `gh`: PR の作成・コメント・編集とレビュー投稿（`gh pr create/comment/edit`、`gh api …/reviews|comments|replies`）を打つ
    Bash のコマンド全体。**`--body-file` に渡すファイルの中身（Write で作る本文）は含まない**ので、PR 本文の数字は過小になる
- 出力は件数・割合だけで、本文は出さない。`--ctx` が出すのも前後1文字の分布だけ
- 指標: 開いた語の出現数（OPEN）、同じ意味の漢語・カタカナ語の出現数（PLAIN）、
  両者の比（開いた語 ÷ 合計）、万字あたりの出現数、全面禁止の言い回し数（BAN）、
  開いた語を1つ以上含む発言の数。使ってよい和語は、どの正規表現にも入れていない
- 誤検出を除く方法:
  - コードブロック・インラインコード・`>` の引用行・パスと URL・「」『』の中を数えない（語そのものへの言及を外すため）
  - 普通の用法を前後の文字で外す。直し: やり直し・見直し・書き直し・立て直しのような「〜し直す」型
    （前の文字で外す。後ろの文字では外さないので、直した・直したい・直しました・直して はすべて数える）。
    写し: 書き写し・映し・写し出す。控え: 控えめ・控える・控えて。測り: 計測り・推測り。
    全面禁止: 「一切」単独は数えず、禁止の述語と組になったときだけ数える
  - 語を話題にした会話（この傘の作業のセッション）は `--exclude-project` で外す
- 限界: **開いた語の比は上限の見積もり**。「確かめる」「直す」は、文脈によっては普通の言葉であり、
  計測では悪癖の用法と区別しきれない。絶対値より、同じ式での前後の差を見る道具として使う。
  悪癖2 は件数が少なく、週ごとの揺れが大きい

### 4.1 試験（実際の Claude Code と合成入力）

試作は `docs/adr/probes/wording-habits/stop_hook_prototype.py`。判定の語・正規表現は `wh.py` と同じものを使う。

- **合成した入力の JSON を直接渡す試験**（8ケース）: 開いた語（確かめ・直し）→ block。全面禁止（二度と〜しない）→ block。
  漢語だけ、使ってよい和語（引く・探す・止める・立てる・回す）、やり直し・見直し・書き写し・控えめ、
  事実としての「一切変更は無い」、コード・「」の中、`stop_hook_active` が真の再入 → いずれも何も出さない
- **実機の試験**（一時ディレクトリで `claude -p --settings <一時ファイル> --model haiku`、1回）:
  hook が起動して結果を返し、返事が2ターンになった（書き直しが起きた）。追加の費用は約0.004ドル。
  ただし試験の指示が「そのまま書き写して」だったので、書き直し後の返事にも元の語が残った。
  **仕組みが動くことは確認できたが、自然な返事で悪癖が減るかは未確認**。実 `$HOME` の設定は触っていない
- 公式文書で確認できた仕様: Stop の入力に `last_assistant_message` と `stop_hook_active` がある。
  `decision: block` か exit 2 で続行させる。連続8回続くと次の block は無視される（`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で変更可）。
  `prompt` 型は `Stop` と `PreToolUse` で使え、`SessionStart` では使えない

## 5. 悪癖2 の扱い

- 悪癖2 は言葉ではなく判断の癖で、**点検で抑えられるのは、言い回しとして表に出た部分だけ**である。
  「一切〜しない」「二度と〜しない」「今後は〜しない」のような宣言の形は C・E の正規表現で検出できる
  （上の試験で確認）。ただし判断そのもの（指摘を禁止に広げる）は検出できない
- メモリ・ほかの会話への指示に広げる行為は、E（メモリへの書き込み・`SendMessage`・`herdr` と `gh` の送信の点検）で止められる見込みがある。
  この調査での件数はメモリ 0件・送る文 2件で、計測上はほぼ出ていないが、持ち主の指摘は件数でなく重さの問題である
- 指示文の書き方としては、「指摘は、その場面で何が悪かったかの話である」と**状況を述べる形**で書き、
  「〜してはいけない」の列挙にしない。規則を作って判断を持ち主に丸投げする形を避ける（計画書 決定的な制約）
- 抑えられない範囲: 宣言の形をとらずに、静かに振る舞いを変える・メモに残す、といった形の広げ方は、言葉の点検では見つからない

## 6. 推奨案（1つ）

**`Stop` hook（command 型）を1本入れ、悪癖1・悪癖2 の両方の言い回しを点検して、該当したときだけ書き直しを促す。**
あわせて、悪癖2 の指示文を状況を述べる形で `claude/CLAUDE.md` に短く足す（A を補助として使う）。

- 理由:
  - A・B・F は指示の置き場で、既に A が効かなかった。強制になるのは hook だけ（公式の記述）
  - D（モデル判定）は境界に強いが、毎ターンの費用と遅延が全返事に乗る。C は無料で高速で、
    境界の誤りは `wh.py` の過去ログでの検査と自動テストで固定できる
  - E は外へ出る前に止められる点で C より確実だが、経路が複数（`SendMessage`・`herdr`・`gh`・メモリ）に分かれ、
    `SendMessage` の matcher は未確認、`gh` は `--body-file` の中身を hook が読む必要がある。`SendMessage`・`herdr` は
    AI 同士の通信が主で持ち主の目に触れない。持ち主が実感する会話の言葉（返事の本文）を先に C で押さえ、
    E は次の手とする。**PR 本文は公開リポでほかの人にも見えるので、E のうち最初に足すのは `gh` の送信**
    （これは持ち主の判断で、孫2 に含めるかどうかを選べる）
  - **C が点検できるのは各ターンの最後の本文だけ**で、ツール呼び出しの合間の本文（開いた語の約24%）は対象外。
    導入後の前後比較は、C の効果を見るために `final` を、全体への効き方を見るために `text` を、どちらも出す
- 期待する効果: 点検に引っかかった返事の次の返事に、理由が文脈として入るので、同じ会話の中での再発が減る
  （**未検証。孫2 が `wh.py` で導入前後を比べる**）。表示済みの返事そのものは消せない
- 副作用と対策:
  - 語を絞らないと**ターンの約40%**（11/10 以降、最後の本文に開いた語がある割合。直した・直したい を数えた値）が止まる水準で、
    書き直しの1ターンの費用が全体に乗る。**初期の語は持ち主が名指しした
    背景2 の語（確かめ・直し・測り・割り出し・控え・写し・造語）に絞り、`wh.py` で語別に該当率を見て、
    普通の用法が多い語は外す**（確かめる・直す・写しは、語形を絞る余地がある）
  - 書き直しの理由は禁止語の羅列にせず、何が悪い場面かを書く（状況の指摘であって全面禁止にしない）
  - `stop_hook_active` が真のときは再点検しない。8連続の上限もある
  - 背景3 の使ってよい和語は正規表現に入れず、自動テストで「止めない」ことを固定する
- 導入の規模（孫2 の作業量）: 触るファイルは `claude/hooks/` に hook のスクリプトと `claude/settings.json` の
  `hooks.Stop`、`claude/CLAUDE.md` の追記（悪癖2 の1段落。持ち主の承認が要る）、
  `shared/helpers.sh` の `links_for_tool()` の確認（DOC-2610150520-c）、`tests/` に境界のテスト、ADR 1本。
  hook は Claude Code 固有で、Codex・OpenCode には届かない（届かないことを ADR とヘルパーに明記する）。
  規模は中程度で、孫1本で足りる見込み
- 入れなかった案: D は費用と遅延が毎返事に乗るので初期案から外した。効果が出ないか、正規表現の境界が
  合わないと分かった場合の次の手として残す。E（`gh` の送信から）は C の効果と該当率を見たあとに追加できる。`SendMessage` を足すなら先に matcher を実機で確認する
