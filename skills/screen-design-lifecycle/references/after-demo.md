# 工程 6: デモを触った後の受け口とボード

実装した画面のデモを、人が触って気づきが出始めたときに読む。読み手は、傘の司令官と、直しを取る人。
分担ボード（工程 5）は差分を一度に洗い出して配る物で、これは**触って出た気づきを少しずつ受ける物**。目的が違うので、別の issue にする。

## 置き場

実装リポに issue を1本立てる。

| 部分 | 役割 | 書く人 |
|---|---|---|
| コメント | **受け口。** 画面・触った所・微妙な点を一言で書く | 触った人（誰でも） |
| 本文 | **ボード。** 司令官がコメントを仕分けて、番号付きの行（`BD-`）で足す | 司令官 |

- 取る人は、コメントで名乗る
- 前の工程の分担ボードの issue は使い回さない。残りを片付けたら閉じる
- 実装リポの issue への書き込みは、リポの規約と人間の指示に従う（書き込みを許されているときだけ）

## 状態

| 状態 | 意味 |
|---|---|
| 仕分け待ち | コメントが出て、司令官がまだ仕分けていない |
| Figma の決め待ち | 見た目の決めを変える件。記録を作っている |
| 実装待ち | 決めが済み（または実装だけがずれていて）、取る人を待っている |
| 実装中 | 名乗った人が取っている |
| 済み | 実装が入り、確認された |

## 仕分けの条件

司令官がコメントを読んで、次のどちらかに分ける。

| 条件 | 扱い |
|---|---|
| 実装だけが Figma からずれている | そのまま「実装待ち」にする |
| 見た目の決めを変える | 「Figma の決め待ち」にして、記録（下調べ → 案 → ユーザーの決定 → Figma → 記録の PR）を作る。記録が入ったら「実装待ち」にし、記録と Figma のノードへリンクする |

**小さい直しも Figma が正。** 実装を先に変えない。実装の側だけ直すと、次の差分の洗い出しで同じ件が出る。

## 1件の流れ

1. コメントを読み、画面と触った所を確かめる。足りなければ、書いた人へ聞く
2. 仕分けて、ボードに `BD-` の行を足す（番号は司令官が連番で配る）
3. 見た目の決めを変える件は、`figma-design-workflow` の1件の流れで記録を作る。番号は決めと記録の連番の続き（記録の番号は傘をまたいで続ける）
4. 記録が入ったら、行の状態と記録へのリンクを更新する
5. 実装は、名乗った人が製品のリポで PR を出す。**傘の孫にしない**

行の本文を書き換えたら、コメントで知らせる（見落としで重ねて取られるのを防ぐ）。

## 出口

- ボードの行が、すべて「済み」か、見送りの理由つきで閉じている
- issue の残りを片付けたら閉じる

## よくある失敗

- 受け口とボードを別の場所に置き、コメントが仕分けられずに溜まる
- 小さい直しだからと実装を先に変え、Figma と食い違う
- 前の分担ボードの issue を使い回して、古い件と新しい件が混ざる
- 見た目の決めを変える件を、記録を作らずに実装へ回す
