# 工程 0: 新しい画面の始め方

新しい画面（例: 画面A の v1、または画面A の v2）の設計を始めるときに読む。読み手は、画面の設計を始める人と司令官。

## 最初に作る文書の順

| 順 | 文書 | 中身 | いつまでに |
|---|---|---|---|
| 1 | 置き場の入口（README か AGENTS） | ディレクトリの構成・読む順・番号の凡例（下の表） | 傘の最初 |
| 2 | 用語ルール | 外へ出す文書で使う言葉・出さない内部名。既にあれば引き継ぐ | 傘の最初 |
| 3 | 現状の把握 | 変える前の画面の状態。何があって、何が困っているか | 画面の案を作る前 |
| 4 | UI と文言の共通方針 | 情報設計・文言のぶれを防ぐ物差し。既にあれば引き継ぐ | 最初の Figma の案を作る前 |
| 5 | FB の一覧 | 変える理由の元（工程 1） | 現状の把握と同時 |
| 6 | ページの役割と定義の文書 | 各ページの役割・業務の流れ・データの定義。数字の分母と状態の言葉 | Figma を作り始める前 |
| 7 | 決めの文書 | 決まっていること（工程 2） | Figma を作り始める前 |
| 8 | 記録の置き場 | 記録の一覧と番号の凡例 | 最初の記録を書く前 |

6 と 7 は、傘を始めた後に「やはり要る」と気づいて作ると、決まりが計画書の本文に散った後になる。**Figma より前に置く**。
引き継げる既存の文書（2・4）は、写さずに指す。

実装への申し送りの文書は、この表に入れない。画面の構成が固まってから書く（[handoff-docs.md](handoff-docs.md)）。

## ディレクトリの骨組み

傘の始めに骨組み（ディレクトリと文書の置き場）を決めて、担当どうしの置き場がぶつからないようにする。
画面ごとにディレクトリを1つ作る形が基本。

```
<画面名>/
├── README.md          入口。読む順と番号の凡例
├── current-state.md   現状の把握
├── decisions.md       決めの文書
├── definitions.md     定義の文書
├── changes/           記録（1件1ファイル。README.md が一覧）
├── handoff/           実装への申し送り（工程 4）
├── gaps/              差分の表（工程 5）
└── archive/           置き換え済みの文書
```

名前は例。リポの既存の決めがあればそれに従う。定義の文書を画面ごとに持つか、共通の場所へ出すかは、画面をまたいで同じ言葉を使うかで決め、
既存の文書を動かす案は司令官へ出す（動かす前に、読んでいる文書のリンクを数える）。

## 番号の凡例（出どころごとの接頭辞）

番号は、出どころごとに違う接頭辞を最初に割り当てる。同じ頭文字が別の物を指す衝突を防ぐため。

| 出どころ | 接頭辞 | 配る人 |
|---|---|---|
| FB（会議・レビューで出た指摘） | `FB-` | 司令官。画面ごとの章を付けてもよい（例: `FB-L-03`） |
| 決め（決めの文書の項目） | `DEC-` | 司令官 |
| 記録 | `NN`（2桁以上の連番） | 司令官が連番で配る。傘をまたいで続ける |
| 計画書の返事待ち・回答 | `ANS-` | 司令官 |
| 実装との差分の件 | `GAP-<束の頭文字>-` | 差分を洗う担当（束ごとに頭文字を決め、`GAP-L-01` のように束をまたいで重ならない形にする。頭文字は `handoff-to-impl.md` の識別子と同じ） |
| デモ後のボードの行 | `BD-` | 司令官 |

- 記録の番号は、担当が取った順でなく、司令官が配る順にする。枝番（71b など）は作らず、別の番号にする
- 欠番にしたときは、理由を一覧に1行書く
- 凡例は置き場の入口に置く。既に別の頭文字で運用が始まっている画面では、新しい凡例との対応表を書く

## 体制の決め方

- 司令官1人＋担当。担当は**画面のまとまりごと**（例: 一覧・詳細・共通の部品）に持つ。作業ごとに会話を作ると、毎回文書を読み直すので消費が大きい
- PR が入っても担当の会話を閉じず、続きの作業を同じ担当へ送る
- 最優先の仕事は、基盤づくりを待たずに先に切り出す

## 傘の始めに決めること

- 置き場の骨組みと番号の凡例（上）
- 決めの文書と定義の文書を誰が書くか（司令官が書き、担当は参照するだけ）
- 返事待ちの一覧の置き場（計画書の中）
- 外へ出す文書で守る言葉・個人情報の扱い（リポの規約を確認する）
- 担当が膨らんだときの区切り（記録を細かく書いておけば、compact の後も続けられる）

## 引き継ぎの文書

司令官や担当が交代する見込みがあるときは、引き継ぎの文書（検討状況・進捗・次の一手）を先に書く。
時間がたつと古くなるので、時点を書き、今の状態の正は計画書の進捗テーブルと決めの文書に置く。更新は文書の先頭に節を足し、本文は「この時点のまま」と断る。

## よくある失敗

- 決めの文書・定義の文書を後から作り、計画書の本文に決まりが散る
- 番号の接頭辞を決めずに始め、FB・差分・ボードの行で同じ頭文字が衝突する
- 引き継ぎの文書を今の状態の正として扱い、古い内容で動く
- 画面の構成が決まる前に申し送りを書き、後で全面に書き直す
