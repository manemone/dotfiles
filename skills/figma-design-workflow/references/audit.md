# 点検スクリプトの使い方

決まりを作ったあと、全画面を数えて外れた所を洗うときに読む。画面を直す PR の前、決まりを変えたとき、変数や部品を触る作業の前後に回す。
スクリプトの雛形は [audit-template.js](audit-template.js)。決めの中身（何を決まりにするか）は
[patterns-visual.md](patterns-visual.md)、進め方は [patterns-process.md](patterns-process.md)「決まり＋全画面の点検」。

**スクリプトは読むだけ。** 正本には何も書かない。決まりの表は雛形の先頭にまとまっていて、利用者が差し替えれば使える形になっている
（雛形の値は全部「例」）。

## いつ回すか

- **画面を直す PR を出す前。** 直す前と後で回し、PR の説明に「点検の新しい違反 0」（増えた件数）を書く
- **決まりを変えたとき。** 文書の決まりと、スクリプトの表を同じ PR で揃える
- **変数・スタイル・部品の本体を触る作業の前後。** 前の数を取っておき、後の数と比べる（下の「書く前の数と比べる」）

## 回し方

1. 決まりの表を自分の傘の決まりに差し替える（次節）
2. コメント行と空の行を落として、Figma の MCP の `use_figma` の `code` に渡す。コードの長さの上限と返り値の上限
   （数十 KB）に収めるため。Figma の公式スキルの `use_figma` の書き方（`figma-use` など）に従う。ここには写さない

   ```sh
   sed -e 's#^\s*//.*$##' -e '/^\s*$/d' skills/figma-design-workflow/references/audit-template.js
   ```

   この `sed` は行頭が `//` の行だけを落とす。行の途中のコメントは残る（文字列の中に `//` を書かない）
3. 呼び出しは 1 回にまとめる。Figma の MCP の回数の上限は傘の全会話で分け合うので、画面ごとに分けて何度も回さない
   （[SKILL.md](../SKILL.md)「上限と自動再開」）
4. 返り値の形:
   - `screens[]`: 画面ごとの `{id, name, rules}`。`rules` は決まりごとの `{count, kinds, samples}`
     （`kinds` は値の種類と数、`samples` は代表のノード id とカードの名前）
   - `totals`: 決まりごとの合計。**合格は全部 0**
   - `snapped`・`lengthPadding`・`positionPadding`・`bandPadding`・`clippedOverflow`: 違反に数えず、数だけ返す物
     （実装で寄せる値・長さに使う余白・位置の指定の余白・帯の余白・親で切れて見えないはみ出し）
   - `reference`: 参考の数（`handmade`・`halt`）。違反の合計には入れない
   - `translucent`: 半透明の塗り・線の数と内訳。`drop` に、決まった数より減った内訳が出る。`totals.translucentDrop` が 0 でなければ、
     不透明度が 1 に戻った所がある

## 決まりの表の差し替え方

雛形の先頭の「設定」の節だけを直す。本体（走査）は触らない。

| 設定 | 差し替えること |
|---|---|
| `PAGE_ID`・`SCREEN_PREFIX` | 点検する作業のページと、画面の枠の名前の頭 |
| `SKIP_COMPONENTS`・`CARD_COMPONENTS` | 点検しない外枠の部品と、「カードの中」の決まりを見る範囲になる部品 |
| `TYPE_SCALE`・`NUMBER_*` | 字の段と、大きい数字の段・色 |
| `SPACING_*`・`RADIUS_*` | すき間・角丸の段、寄せる値、例外 |
| `GRAY_*`・`BORDER_*` | 灰色の地・枠線の箱の決まりと、数えない部分木の名前 |
| `ROLE_*` | 変数の名前の組（役割）と、置いてよい層の種類 |
| `ICON_*`・`TABLE_ROW_RE` | アイコンの置き場の型。使わなければ `ICON_COMPONENT` を `null` に |
| `SCRIM_NAME_RE`・`TRANSLUCENT_EXPECTED` | 幕の名前（無ければ `null`）と、半透明の決まった数 |
| `EXCEPTIONS` | 決まりごとの例外のノード id |

決まりのうち使わない物は、設定を空にするか、表の値を何にも当たらない値にして 0 のままにする。必要な決まりが雛形に無ければ、
同じ形（走査の中で `push(bucket, '決まりの名前', ...)` を呼び、`EXCEPTIONS` に空の配列を足す）で足す。

**除外は名前で書く。** 大きさで除外すると、別の物まで見逃す。

## 例外の足し方

- 「決まりの例外として残す」と決めた物は、`EXCEPTIONS` にノード id を足す。理由をコメントに書く（場所と回数も）
- **点検の誤り**（決まりでは違反でない物を拾った）は、名前の除外か条件の方を直す。足した理由をコメントに書く
- 決まりどおりの作りが違反に数えられたら、**決まりの方を見直す**。手本と同じ作りを「手組み」と数えるなら、その数は違反でなく参考の数にする

違反が出たら、1 件ずつ「直す・例外・点検の誤り」に分ける。分けずに例外を足さない。

## 1 つの決まりを詳しく見る

設定の `DETAIL` に決まりの名前（例 `'overflow'`）か、名前の配列（例 `['border', 'type']`）を入れる。代表と内訳が多めに返り、
ノードと親の名前も付く。返り値の上限を超えたら、配列を短くする。終わったら `null` に戻す。

## 書く前の数と比べる

**点検は「書く前の数」と比べる。後の数どうしで比べると見逃す。** 変数への結び直しや、変数の値の書き換えで、塗りの不透明度は
1 に戻ることがある（[patterns-visual.md](patterns-visual.md)「色の 2 段」）。作業の途中で数を取り直して比べると、
戻った後の数を基準にしてしまい、半透明が消えたことに気づかない。

1. 変数・スタイル・部品を触る作業の**前**に、点検を回す。半透明の内訳と数、違反の合計を控える
2. 控えた半透明の内訳を `TRANSLUCENT_EXPECTED` に写す。画面を変えて半透明を足した・消したときは、ここも直す
3. 作業の後に回し、`translucent.drop` と `totals.translucentDrop` が 0 であることを確かめる。減っていれば、戻った所を直す

前の数は記録にも書く（[record.md](record.md)）。レビュワーは記録の前後の数を見る。

## 確かめ方

Figma の外では動かないので、リポの中で回すテストは持たない。手元では構文だけを確かめる。

```sh
node --check skills/figma-design-workflow/references/audit-template.js
```

差し替えたスクリプトも、同じく `node --check` を通してから渡す（雛形は `main` 関数の中身を `return main();` で返す形なので、そのまま通る）。
動作の確かめは、Figma の MCP で回した返り値で行う。

- 返り値が返ること・`totals` の決まりの名前が揃っていること
- 既知の違反が 1 つあるなら、それが数えられること（逆に、直した物が 0 に戻ること）
- 例外を足したあと、その物だけが数から消えること

雛形を差し替えたスクリプトは、それを使う傘のリポに置く（置き場は利用者のリポの決めに任せる）。このスキルの雛形は直さない。
