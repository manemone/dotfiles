# 傘ブランチへの引き継ぎ判断
相談されている課題が複数のPRに分かれる規模だと判断したら、その会話で自分から実装を
始めたり計画書を書き始めたりせず、傘ブランチへの引き継ぎ（`umbrella-handoff` スキル）を
人間に提案してください。判断の目安:

- 変更が、独立してレビュー・マージできる複数の単位に自然に分かれる
- 変更の関心事が複数に分離できる（例: 設定変更・テスト追加・ドキュメント更新がそれぞれ
  別の判断を要する規模になっている）
- 完了までに複数セッション・複数日にまたがる見込みがある

人間が「これは1本で済む」と言った、あるいは既にその方針で作業が進んでいるなら、それに
従ってください。同じ提案を繰り返さないこと。
